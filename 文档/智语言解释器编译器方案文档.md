#### 1.2 项目定位

智语言是一门静态强类型的全中文编程语言。它提供统一的命令行工具 `智语言`，支持两种运行模式：

- **解释模式**：通过内置的解释器直接执行源代码，达到"修改即运行"的即时反馈体验。命令为 `智语言 运行`。
- **编译模式**：通过编译器将源代码编译为原生可执行文件，获得最佳运行时性能。命令为 `智语言 构建`。

这两种模式共享同一套前端实现（词法分析、语法分析、语义分析），并基于统一的低阶中间表示（LIR）进行后端分流。因此，无论用户选择哪种模式，语言的行为语义完全一致。

本项目即为智语言的官方解释器与编译器实现，使用 Rust 语言开发。它不仅仅是语言规范的工程落地，也是对整个中文编程生态的完整支撑——从编写、调试到构建发布，提供一站式的开发体验。

工具链自身采用三层 crate 架构：

- **语言管理器**：CLI 入口与命令调度，负责解析参数、调用下层 API、格式化输出。
- **项目管理**：工程管理知识，包括项目检测、目录结构、配置解析、路径计算等。
- **库管理**：包管理知识，包括库的安装、卸载、更新、封装、发布，以及注册表通信和校验。

#### 1.4 核心概念速览

**前端、LIR 与后端**

- **前端**：解释器和编译器100%共享的代码模块。负责将智语言源代码经过词法、语法、语义分析，最终转化为一种标准化的低级中间表示（LIR）。前端只做一件事：**源码进，LIR出**。
- **LIR（低阶中间表示）**：全称 Low-level Intermediate Representation。它是整个工具链的"语义宪法"——由基本块和带类型的三地址码指令构成。前端生成 LIR，所有后端（解释器、编译器）都从同一个 LIR 出发生成可执行码。LIR 保证了解释模式和编译模式下的程序行为完全一致。
- **后端**：指接受 LIR 并生成最终可执行形态的模块集合。目前有两条后端路径：解释器后端和编译器后端。

**双模式**

- **解释模式**：命令 `智语言 运行`。将 LIR 翻译为自定义字节码，在寄存器虚拟机中解释执行。追求**即时反馈**，支持秒级启动和交互式调试。
- **编译模式**：命令 `智语言 构建`。将 LIR 翻译为 Cranelift IR，经优化后生成原生机器码，链接为独立可执行文件。追求**极致性能**，默认开启速度优化。
- **字节码与虚拟机**：字节码是 LIR 的紧凑二进制序列化形式，专为解释器设计。寄存器虚拟机是解释执行字节码的引擎，内部维护虚拟寄存器文件和调用帧栈，指令格式与 LIR 三地址码直接映射。

**中间表示层级**

- **AST（抽象语法树）**：语法分析的直接产物，完整对应源码结构，不带类型信息。
- **HIR（高级中间表示）**：语义分析的产物。在 AST 基础上携带了完整的类型标注和符号表引用，是有名任意类型单态化和类型检查完成后的形态。
- **LIR（低阶中间表示）**：由 HIR 降级转换而来。擦除了高层类型信息，控制流被结构化为基本块，是前后端之间的**唯一接口**。

**执行与运行时**

- **Cranelift**：Rust 生态的代码生成器，智语言编译模式默认的编译后端。它将 LIR 翻译为原生机器码，编译速度快，生成代码质量良好，且无需 C++ 依赖。
- **统一运行时**：解释器和编译器共享的底层运行时库。提供统一的值表示（`运行时值`，32字节扁平结构体）、全局堆管理、COW写时复制、标记-清除垃圾回收、异常处理、系统调用和并发原语。解释器直接调用运行时 API，编译器通过 C ABI 调用同一套 API，双模式行为天然一致。
- **垃圾回收（GC）**：自动管理堆内存的机制，由统一运行时实现。所有复合类型（数组、映射、文本、结构体实例等）都由 GC 负责回收，双模式共用同一套 GC 算法。
- **任务**：智语言的并发执行单元。通过 `并发.启动任务` 启动，任务之间通过**通道**安全通信。任务调度由统一运行时管理。

**全中文约定**

- **全中文实现**：本项目的 Rust 源代码中，所有自定义标识符（函数名、变量名、结构体名等）一律使用中文。命令、参数、错误信息也全部使用中文。唯一的例外是 Rust 关键字和 Cargo 强制要求的包名（如 `csl-frontend`）。

> 以上概念的精确定义和更多细节请参见**附录A 术语表**。

#### 1.5 设计原则

##### 1.5.1 LIR 为界，双端守一

解释器和编译器从同一个低阶中间表示（LIR）出发生成可执行码。LIR 是整个工具链中唯一的"语义契约层"，它精确定义了：

- 整数溢出的行为
- 浮点数遵循的精度标准（IEEE 754）
- 空值的检查点与错误处理语义
- 有名任意类型单态化后的具体调用签名
- **索引与查找返回值约定**：所有数组、映射、文本的索引均为 1-based，后端需统一转换为底层实现。查找类指令未找到时返回 0。整数除零（`/`、`%%`、`%`）统一抛出运行时异常，小数除零遵循 IEEE 754 产生特殊值。

解释器的字节码虚拟机和编译器的 Cranelift 后端都必须严格遵守 LIR 的语义约定。这就从根源上杜绝了"解释模式下程序能运行，编译后行为却不一样"的问题。

##### 1.5.2 脚本求快，工程求优

两种运行模式面向不同的使用场景，设计目标截然不同：

| 模式                     | 目标                                   | 关键指标                                     |
| :----------------------- | :------------------------------------- | :------------------------------------------- |
| 解释模式 (`智语言 运行`) | 极速启动，修改即运行，开发调试友好     | 启动时间 < 0.5s，支持字节码缓存              |
| 编译模式 (`智语言 构建`) | 生成高性能独立可执行文件，适合生产部署 | 运行时性能接近 C/Rust 原生水平，默认开启优化 |

解释模式不必为性能牺牲反馈速度，编译模式不必为构建速度牺牲运行效率。由于已经有解释模式提供即时反馈，编译模式默认追求最快执行速度，双模式各司其职，用户根据所处开发阶段自由选择。

##### 1.5.3 前端统一，后端可换

词法分析、语法分析、语义分析、高级中间表示（HIR）构建以及 HIR→LIR 的降级转换，这五个步骤与"如何运行"无关，它们仅负责将智语言源代码翻译为结构化的 LIR。这一整套前端代码在两个模式中 **100% 共享**。

LIR 之后的后端则设计为可插拔的架构：目前提供解释器后端（生成字节码并在寄存器虚拟机上执行）和编译器后端（生成 Cranelift IR 并生成机器码）。未来如有需要，可以继续接入更多后端，而无须修改前端一行代码。

**关键架构演进**：在最新的实现中，解释器和编译器进一步共享了**统一运行时**。该运行时提供单一的值表示、全局堆、COW、GC 和并发原语。解释器直接使用运行时，编译器通过 C ABI 调用运行时，确保双模式在数据层和语义层完全统一。

#### 1.6 关键设计决策

**为什么用 Cranelift 而不是 LLVM？**

Cranelift 是纯 Rust 生态的代码生成器，编译速度极快，无需 C++ 依赖。引入 LLVM 虽然能获得更强的优化能力，但会显著增大安装包体积（50MB+ vs 10-20MB），增加构建环境复杂度，并带来版本锁定的维护负担。由于日常开发有解释模式兜底，编译模式追求的是"生成可执行文件"的能力和"接近原生"的性能，Cranelift 完全满足需求。LLVM 作为未来可选项保留，但不作为默认后端。

**为什么编译模式默认 speed 而不是 none？**

解释模式已经覆盖了快速反馈场景（修改即运行）。当用户选择编译模式时，意味着他们需要的是生产部署用的可执行文件，此时执行性能优先于构建速度。因此编译模式默认开启 Cranelift 的 speed 优化级别。

**为什么 FFI 基于 C ABI 而不是 Rust 专有协议？**

C ABI 是业界唯一的跨语言稳定二进制接口标准。选择 C ABI 意味着智语言可以直接调用操作系统 API 和任何提供 C 兼容接口的库（包括 Rust 通过 `extern "C"` 导出的库）。如果只支持 Rust 专有协议，标准库本身将无法实现（因为需要调用 POSIX/Windows 系统调用）。

**为什么数组索引从 1 开始？**

智语言面向中文母语者，生活中数数从"第1个"开始是自然习惯。1-based 索引降低了初学者的认知门槛，使代码读起来更接近自然语言。这一决策在解释器和编译器内部需要额外处理（将用户索引转换为内部偏移），但这份复杂度由工具链承担，用户无感知。

**为什么标准库用智语言自身编写 API 层？**

标准库的 API 层用智语言编写，底层通过统一运行时调用系统能力。API 层编译为 LIR 后供两种模式共享。这不仅是"自举验证"的需要——标准库能编译通过并正确运行，本身就证明了解释器和编译器的正确性——也保证了标准库的行为在两种模式下完全一致。

**为什么采用统一运行时架构？**

解释器和编译器共享同一套运行时（值表示、堆管理、GC、COW、并发原语）是从"逻辑统一"迈向"物理统一"的关键一步。它消除了解释器私有堆和值枚举带来的双副本问题、桥接转换开销（每次堆操作节省两次深拷贝），并使 GC 和 COW 逻辑成为单一真相源。双模式的行为一致性不再依赖桥接函数的正确性，而是由共享代码天然保证。

##### 1.7.3 数据流向

1. **用户源码** 作为 UTF-8 编码的文本文件输入。
2. **词法分析器** 将字符流切分为词条（Token）序列，每个词条携带源码位置（行号、列号）。
3. **语法分析器** 将词条序列解析为抽象语法树（AST），同时检测语法错误。
4. **语义分析器** 遍历 AST，进行符号表构建、类型推断与检查、任意类型单态化、空值安全检查，最终生成带类型标注的高级中间表示（HIR）。
5. **降级转换器** 将 HIR 转换为 LIR，擦除高层类型细节，但锁定所有与行为相关的语义。LIR 中明确约定所有索引为 1-based，查找未找到返回 0，整数除零（`/`、`%%`、`%`）统一抛出运行时异常。
6. **LIR 分发**：
   - 若是解释模式，LIR 被送入字节码生成器，产出字节码文件（含源码映射），寄存器虚拟机加载字节码并解释执行。内部数组/映射/文本操作自动将 1-based 索引转为 0-based 内部偏移。
   - 若是编译模式，LIR 被送入 Cranelift IR 生成器，经优化和代码生成后链接为可执行文件。在生成的 IR 中会显式插入 `索引 - 1` 的调整指令。
7. **运行时交互**：无论哪种模式，所有堆操作（数组追加、映射插入、文本拼接等）、系统调用、异常处理和并发操作最终都调用统一运行时的同一套 API。解释器直接 Rust 调用，编译器通过 C ABI 调用。

#### 1.8 全中文实现约定

##### 1.8.1 Rust 代码标识符中文化

解释器与编译器采用 Rust 语言编写。在 Rust 源代码中，**函数名、变量名、结构体名、枚举类型名、模块文件名**等所有自定义标识符，只要其表达的概念在中文中有对应的清晰词汇，一律使用中文命名。对于 Rust 本身的关键字、标准库 trait 名称（如 `Drop`、`Iterator`）以及业界通用缩写（如 `LLVM`、`IR`），仍保留原样。

##### 1.8.2 命令行接口中文化

`智语言` 命令行工具的**命令、子命令、参数名、标志以及所有帮助信息**全部使用中文。

##### 1.8.3 错误与诊断信息中文化

所有编译期错误、运行时错误、警告信息以及帮助建议，都必须使用中文输出，严格遵循 **4.1 错误报告规范** 中定义的格式模板。

##### 1.8.4 标准库与 API 中文化

标准库中的**模块名、函数名、方法名**完全沿用《智语言编程规范》第四章和第五章的中文命名。解释器与编译器在加载标准库时，直接识别这些中文名称，不需要任何额外的翻译层。

##### 1.8.5 文档与注释优先使用中文

解释器与编译器项目自身的代码注释、设计文档、贡献指南、API 文档等，优先使用中文撰写。如有必要提供英文版本，则英文版本作为辅助参考，中文版本为权威原文。

### 第二部分 前端设计

#### 2.1 前端总览

##### 2.1.1 前端职责与边界

统一前端是解释器和编译器完全共享的代码模块。它的唯一职责是：**将智语言源代码转换为类型正确、语义明确的 LIR 模块**。前端不关心 LIR 之后是走虚拟机执行还是走 Cranelift 生成机器码，也不包含任何与运行模式相关的逻辑。

**输入与输出**：

| 项目       | 说明                                                         |
| :--------- | :----------------------------------------------------------- |
| **输入**   | UTF-8 编码的智语言源文件（`.智` 文件），可包含多个模块       |
| **输出**   | `Lir模块` 列表，每个模块对应一个源文件，附带完整的类型标注、符号信息和源码位置映射 |
| **副作用** | 在此阶段发现的所有语法错误、类型错误、语义错误、命名错误，通过统一的诊断收集器输出，遵循 4.1 错误报告规范 |

**前端内部流水线**：

```
源码文本
    │
    ▼
┌──────────┐
│ 词法分析  │ → 词条(Token)流，每个词条携带源码位置
└────┬─────┘
     │
     ▼
┌──────────┐
│ 语法分析  │ → 抽象语法树(AST)，保留完整的源码位置信息
└────┬─────┘
     │
     ▼
┌──────────┐
│ 语义分析  │ → 高级中间表示(HIR)，带类型标注和符号表
└────┬─────┘
     │
     ▼
┌──────────┐
│ 降级转换  │ → 低阶中间表示(LIR)，类型擦除，语义固化
└──────────┘
```

**错误处理策略**：

前端在分析过程中发现错误时，不会立即中止。错误恢复策略如下：

- **词法错误**：跳过非法字符或非法序列，尝试从下一个有效字符继续扫描。
- **语法错误**：采用恐慌模式恢复。当某个语法结构无法匹配时，报告错误，并向后跳过词条直到找到同步词条（如 `结束`、`否则`、`否则如果`、分号、换行等），然后继续解析下一条语句或定义。
- **语义错误**：报告错误后继续遍历 AST，尽可能在一次分析中收集所有错误。

所有错误被收集到一个诊断收集器中，在前端分析结束后按行号排序输出。

##### 2.1.2 诊断收集器

诊断收集器是前端中的独立组件，负责接收来自词法、语法、语义各阶段报告的错误和警告，按规则排序和截断，最后调用格式化函数输出最终的错误文本。

```rust
struct 诊断收集器 {
    诊断列表: Vec<诊断信息>,
    错误计数: usize,
    警告计数: usize,
    最大错误数: usize,  // 默认 100
    最大警告数: usize,  // 默认 50
}
```

诊断收集器的核心方法：

- `报告(诊断信息)`：向收集器中添加一条诊断。如果已达到对应级别的数量上限，则记录截断计数而不添加。
- `输出所有诊断()`：按行号列号排序，错误优先于警告，然后调用格式化函数逐条输出。

#### 2.2 词法分析

##### 2.2.1 词条定义

每个词条由类型、可选值和位置组成。词条类型枚举按功能分为以下分类：

**关键字类**（共43个，含4个可省略的：`变量`、`函数`、`公开`、`传值`）：

- 变量与常量：`变量`（可省略）、`常量`
- 类型定义：`结构体`、`枚举`、`任意`、`接口`、`适配`
- 流程控制：`如果`、`否则如果`、`否则`、`结束`
- 循环与跳转：`循环`、`遍历`、`跳出`、`继续`
- 函数与返回：`函数`（可省略）、`返回`
- 模块系统：`导入`、`展开`、`别名`
- 访问控制：`公开`（可省略）、`私有`
- 参数传递：`传值`（可省略）、`传引用`
- 逻辑运算：`且`、`或`、`非`、`属于`、`不属于`
- 类型与值：`整数`、`小数`、`文本`、`布尔`、`空值`、`真`、`假`
- 异常处理：`捕获`、`异常`、`始终`、`抛出`
- 外部函数接口：`外部`、`导出`
- 其他：`自身`

> **注意**：`初始化`、`清理`、`启动程序` 不是关键字，它们是"特定条件保留标识符"——在词法层面被扫描为普通标识符，在语义分析阶段由编译器在特定上下文中识别并赋予特殊语义。其中 `启动程序` 在模块顶层作为函数名时被识别为程序入口，`初始化` 和 `清理` 在结构体内部作为方法名时被识别为特殊成员。

**字面量类**：`整数字面量`、`小数字面量`、`文本字面量`、`真`、`假`、`空值`

**标识符类**：`标识符`

**运算符类**：
- 算术：`+`、`-`、`*`、`/`、`%%`、`%`、`^`
- 比较：`>`、`<`、`==`、`!=`、`>=`、`<=`、`===`、`!==`
- 赋值：`=`、`+=`、`-=`、`*=`、`/=`、`%%=`、`%=`、`^=`、`&=`、`|=`、`<<=`、`>>=`
- 位运算：`&`、`|`、`~`、`!|`、`<<`、`>>`

> **注意**：异或运算符 `!|` 不提供复合赋值形式。如需使用，请写 `甲 = 甲 !| 乙`。

**分隔符类**：`(`、`)`、`{`、`}`、`[`、`]`、`,`、`;`、`:`、`.`

**特殊类**：`语句分隔符`（来源为换行或分号）、`文件结束`

**词条数据结构**：

```rust
struct 词条 {
    类型: 词条类型,
    值: 词条值,       // 对于字面量存实际值，其余存 None
    位置: 源码位置,    // 行号、列号、文件路径
}

struct 源码位置 {
    文件: 字符串,
    行号: usize,   // 从 1 开始
    列号: usize,   // 从 1 开始，按 Unicode 码点计算
}
```

##### 2.2.2 扫描算法

词法分析器内部维护一个字符指针（当前位置），通过 `peek` 和 `advance` 两个基本操作进行扫描。

**核心扫描循环**：

```
当 未到达文件末尾:
    跳过空白字符（空格、制表符、中文空格 \u3000）
    跳过换行符（生成 语句分隔符 词条，记录行号+1、列号归1）
    跳过注释（单行 //、多行 /* */、文档 //** **/）
    尝试匹配字符串字面量（以 " 开头）
    尝试匹配数字字面量（以数字开头）
    尝试匹配标识符或关键字（以中文/下划线开头）
    尝试匹配运算符和分隔符（单字符或双字符）
    分号 → 生成 语句分隔符 词条
    如果是无法识别的字符 → 报告词法错误
```

**标识符扫描规则**：

扫描连续的中文字符、半角数字和下划线。首字符必须以中文或下划线开头，不能以数字开头。将扫描到的字符串在关键字映射表中查找，如果命中则为对应关键字词条，否则为用户标识符词条。

**标识符字符合法性校验**：

标识符只能使用中文简繁汉字、半角数字、半角下划线。禁止使用英文字母、拼音、中英文混用。当检测到非法字符时，报告词法错误：

```
第3行5列 | 错误：命名错误：标识符【age】含非法字符（英文字母），
          标识符只能使用中文简繁汉字、半角数字、半角下划线
帮助：请将标识符改为中文名称，如"年龄"
```

##### 2.2.3 全角标点检测

在扫描运算符和分隔符时，增加对全角标点的检测：

| 全角字符（错误） | 对应的半角字符（正确） |
| :--------------: | :--------------------: |
|    `（` `）`     |        `(` `)`         |
|       `，`       |          `,`           |
|       `；`       |          `;`           |
|       `：`       |          `:`           |
|     `"` `"`      |          `"`           |

当检测到全角标点时，报告一个带有明确修复建议的错误：

```
第5行10列 | 错误：语法错误：使用了全角标点符号【，】
帮助：编程中请使用半角逗号 , 而非中文逗号 ，。全角和半角标点不能混用。
```

**文件路径前置校验**：

在文件加载之前，对文件路径中的每一段（目录名和文件名）进行字符合法性检查。目录名和文件名只能使用中文简繁汉字、半角数字、半角下划线、半角点。禁止使用英文字母、连字符、全角标点符号。

```
[智语言] 错误：路径不合法：【src/主程序.智】中【src】含英文字母，
        文件夹名只能使用中文简繁汉字、半角下划线、半角数字、半角点
帮助：请将文件夹改为中文名称，如"源码"
```

##### 2.2.4 转义序列处理

智语言使用中文关键词转义序列。当在字符串中遇到 `\` 时，读取其后的中文关键词并转换为对应的字符。

**转义映射表**：

| 源代码写法 | 转换结果            |
| :--------- | :------------------ |
| `\换行`    | 换行符（LF）        |
| `\回车`    | 回车符（CR）        |
| `\制表`    | 制表符（Tab）       |
| `\退格`    | 退格符（Backspace） |
| `\换页`    | 换页符（Form Feed） |
| `\空字符`  | 空字符（Null）      |
| `\引号`    | 双引号 `"`          |
| `\反斜杠`  | 半角反斜杠 `\`      |

转义序列在词法分析阶段即被转换为实际字符。LIR 和字节码中存储的是转换后的字符，不再保留转义序列形式。

**注释处理**：

- **单行注释** `//`：从 `//` 到行尾的内容全部跳过。
- **多行注释** `/* */`：从 `/*` 开始到 `*/` 结束，中间的所有内容跳过。不支持嵌套。如果到达文件末尾仍未找到结束标记 `*/`，报告语法错误"多行注释未闭合，缺少 */"。
- **文档注释** `//** **/`：功能同多行注释，但内容可能被后续的文档生成工具提取。在前端阶段，直接作为普通多行注释跳过。

##### 2.2.5 语句分隔符处理

词法分析器在处理换行和分号时，采用"原生识别"策略——两者都被直接识别为 `语句分隔符` 词条，平等对待，不进行自动插入或转换。

**识别规则**：

- **换行符**（`\n`、`\r\n`）：当换行符出现在非括号、非代码块内部时，被识别为 `语句分隔符` 词条。连续的多个换行符只产生一个 `语句分隔符`。括号内的换行符被忽略。
- **分号**（`;`）：始终被识别为 `语句分隔符` 词条。分号前后的空格和换行符被跳过。

**词条生成**：

```
换行 → 词条 { 类型: 语句分隔符, 值: 换行, 位置: ... }
分号 → 词条 { 类型: 语句分隔符, 值: 分号, 位置: ... }
```

语法分析器在解析语句时，将 `语句分隔符` 作为语句结束的信号。当解析完一条表达式语句后，如果下一个词条是 `语句分隔符`，则结束当前语句并开始解析下一条语句。如果下一个词条是 `结束` 或其他关键字，也意味着当前语句结束。

**分号禁用检查**：

语法分析阶段根据上下文拒绝不合法的分号使用：

1. 控制流关键字（`如果`、`否则`、`循环`、`捕获`、`异常`、`始终`）后不允许出现分号
2. `结束` 关键字后不允许出现分号
3. 循环的三段式中不允许用分号替代逗号
4. 函数参数列表中不允许用分号替代逗号
5. 类型声明中不允许用分号替代 `|` 或 `:`
6. `导入` 语句后不允许用分号分隔多个导入

#### 2.3 语法分析

语法分析器（Parser）将词法分析器输出的词条流，按照智语言的语法规则，构建出抽象语法树（AST）。语法分析器采用**递归下降 + Pratt 解析**的方式实现。

##### 2.3.1 为什么选择递归下降 + Pratt

| 方式         | 优点                                                 | 缺点                                           |
| :----------- | :--------------------------------------------------- | :--------------------------------------------- |
| 解析器生成器 | 自动生成，修改语法后重新生成即可                     | 错误信息是英文且不友好，难以实现全中文错误提示 |
| 递归下降     | 完全手写控制，错误信息可精确到具体上下文             | 左递归需要手动消除                             |
| Pratt 解析   | 处理运算符优先级极其简洁，只需为每个运算符定义优先级 | 表达式之外的结构不适用                         |

智语言的语法设计（全中文关键字、代码块以 `结束` 闭合、中英文混合运算符）使得手写解析器能够给出最精确、最符合中文习惯的错误信息。因此选择递归下降处理语句和定义结构，Pratt 解析处理表达式中的运算符优先级。

##### 2.3.3 递归下降解析

解析器内部维护当前词条的位置指针，提供 `peek` 和 `consume` 两个基本操作。

**程序入口解析**：

```
解析程序():
    导入列表 = []
    顶层定义列表 = []
    入口 = None

    当 当前词条 不是 文件结束:
        如果 当前词条 是 导入:
            导入列表.追加(解析导入声明())
        否则如果 当前词条 是标识符 且 值为"启动程序":
            入口 = 解析启动程序()
        否则:
            顶层定义列表.追加(解析顶层定义())

    返回 程序 { 导入列表, 顶层定义列表, 入口 }
```

> **注意**：`启动程序` 不是关键字，它是"特定条件保留标识符"。词法分析将其扫描为普通标识符，语法分析在模块顶层遇到名为 `启动程序` 的标识符后跟 `():` 时，按程序入口的语法规则解析。语义分析阶段检查其唯一性。

**枚举定义解析**：

枚举定义使用冒号引导、`结束`闭合的代码块风格。枚举成员通过换行分隔。分号在语法上也合法（分号和换行在词法分析阶段被平等识别为语句分隔符），但推荐使用换行，保持视觉清晰。

```
解析枚举定义():
    消耗关键字 '枚举'
    枚举名 = 消耗标识符()
    消耗 ':'
    成员列表 = []
    当 当前词条 不是 '结束':
        成员名 = 消耗标识符()
        如果 当前词条 是 '(':
            参数列表 = 解析参数列表()
        否则:
            参数列表 = []
        成员列表.追加(枚举成员 { 成员名, 参数列表 })
        如果 当前词条 是 语句分隔符:
            消耗当前词条()
    消耗 '结束'
    返回 枚举定义 { 枚举名, 成员列表 }
```

**异常控制解析**（四段式）：

```
解析异常控制():
    消耗关键字 '捕获'
    消耗 ':'
    危险块 = 解析代码块()
    
    异常块 = None
    如果 当前词条 是 '异常':
        消耗 '异常'
        消耗 ':'
        异常块 = Some(解析代码块())
    
    始终块 = None
    如果 当前词条 是 '始终':
        消耗 '始终'
        消耗 ':'
        始终块 = Some(解析代码块())
    
    消耗 '结束'
    返回 异常控制 { 危险块, 异常块, 始终块 }
```

##### 2.3.4 Pratt 表达式解析

表达式解析采用 Pratt 算法，每个运算符关联一个优先级，通过递归调用处理不同优先级的子表达式。

**运算符优先级**（与《智语言编程规范》附录 B 一致）：

| 优先级 | 运算符                                                       |
| :----: | :----------------------------------------------------------- |
|   1    | `()` 括号                                                    |
|   2    | `非`、`~`、`-`（取负）                                       |
|   3    | `^` 幂                                                       |
|   4    | `*`、`/`、`%%`、`%`                                          |
|   5    | `+`、`-`                                                     |
|   6    | `<<`、`>>`                                                   |
|   7    | `&` 位与                                                     |
|   8    | `!|` 异或                                                    |
|   9    | `|` 位或                                                     |
|   10   | `>`、`<`、`==`、`!=`、`>=`、`<=`、`===`、`!==`               |
|   11   | `且`、`属于`、`不属于`                                       |
|   12   | `或`                                                         |
|   13   | `=`、`+=`、`-=`、`*=`、`/=`、`%%=`、`%=`、`^=`、`&=`、`|=`、`<<=`、`>>=` |

`属于` 和 `不属于` 作为中缀运算符，Pratt 绑定力与 `且` 相同（第11级）。左侧操作数是元素，右侧操作数是容器或映射。

##### 2.3.5 语法错误恢复

当解析器期望某个特定词条但发现不匹配时：

1. 生成一条语法错误诊断信息
2. 进入恐慌恢复模式：向后持续消耗词条，直到遇到一个**同步词条**
3. 同步词条包括：`结束`、`否则`、`否则如果`、`异常`、`始终`、`语句分隔符`（换行或分号）、`}`、`结构体`、`函数`、`接口`、`枚举`

一旦找到同步词条，解析器就退出恢复模式，继续解析下一个语句或定义。

---

#### 2.4 语义分析

语义分析器（Semantic Analyzer）遍历 AST，完成符号表构建、类型推断与检查、任意类型单态化、空值安全检查，最终生成带类型标注的高级中间表示（HIR）。

##### 2.4.1 符号表设计

符号表按作用域组织为一个栈式结构。每个作用域包含该作用域内声明的所有符号。

```rust
struct 符号表 {
    作用域栈: Vec<作用域>,
    模块注册表: HashMap<字符串, 模块符号>,
}

struct 作用域 {
    符号映射: HashMap<字符串, 符号>,
    作用域类型: 作用域类型,
}

enum 作用域类型 {
    全局,
    函数,
    代码块,
    结构体,
}

struct 符号 {
    名称: 字符串,
    符号类型: 符号类型,
    是否公开: bool,
    是否可变: bool,
    定义位置: 源码位置,
}

enum 符号类型 {
    变量 { 类型: 类型信息 },
    函数 { 形参类型: Vec<类型信息>, 返回类型: Option<类型信息> },
    结构体 { 字段列表: Vec<字段符号>, 方法列表: Vec<函数符号> },
    接口 { 方法声明列表: Vec<方法声明> },
    枚举 { 枚举成员列表: Vec<枚举成员信息> },
    类型标记名称 { 约束范围: Vec<类型信息> },
}
```

**特定条件保留标识符**：

`启动程序`、`初始化`、`清理` 不是关键字，它们是"特定条件保留标识符"——在词法层面被扫描为普通标识符，在语义分析阶段由编译器在特定上下文中识别并赋予特殊语义。

- `启动程序`：在模块顶层作为函数名时，被识别为程序唯一入口。语义分析器检查：每个程序最多定义一个 `启动程序`，且该函数不能有参数。
- `初始化`：在结构体内部作为方法名时，被识别为结构体特殊成员。语义分析器检查：该方法没有自己的参数列表（括号内永远为空），不能写返回类型，不能重载，方法体内直接使用结构体的全局参数。可使用无返回值的 `返回` 语句提前退出。
- `清理`：在结构体内部作为方法名时，被识别为结构体特殊成员。语义分析器检查：该方法没有自己的参数列表，不能写返回类型，不能重载。

**作用域操作**：

- `进入作用域(作用域类型)`：将新作用域压入栈顶
- `离开作用域()`：弹出栈顶作用域
- `声明符号(符号)`：在当前作用域中插入符号，如果同名符号已存在则报告重复声明错误
- `查找符号(名称)`：从栈顶向栈底逐层查找，返回第一个匹配的符号

**私有符号的作用域**：`私有` 关键字可用于**结构体成员**和**模块顶层**。可见性检查在符号解析时进行，访问私有符号的报告为编译错误。

**结构体参数的作用域**：结构体括号里的参数是全局参数——数据参数和带有类型标记名称的参数地位完全平等，都在整个结构体作用域内有效。字段定义、初始化方法、普通方法都可以直接使用这些参数。初始化方法不需要重新声明结构体参数，直接引用即可。

##### 2.4.2 类型推断

智语言是静态强类型语言，但允许在变量声明时省略类型标注。类型推断在语义分析阶段完成。

**基本推断规则**：

- 变量声明 `年龄 = 18`：从赋值表达式推断类型。
- 有默认值的参数 `姓名 = "未命名"`：从默认值推断类型。
- 容器类型 `[1, 2, 3]`：从元素推断。
- 空容器 `[]`：无法推断，必须在上下文中获得类型。
- **函数类型返回类型可省略**：当函数类型注解中省略返回类型时，编译器自动补为 `空值`。因此 `函数()` 等价于 `函数() 空值`。

**类型推断数据结构**：

```rust
enum 类型信息 {
    基本类型(基本类型),
    数组(Box<类型信息>),
    映射(Box<类型信息>, Box<类型信息>),
    结构体(字符串, Vec<类型信息>),
    枚举(字符串),
    有名任意类型 { 标记名称: String, 约束范围: Vec<类型信息> },
    匿名任意类型 { 约束范围: Vec<类型信息> },
    函数类型(Vec<类型信息>, Box<类型信息>),
    未推断,
    推断错误,
}
```

> **注意**：原方案中的 `联合(Vec<类型信息>)` 变体已删除，其功能完全由 `匿名任意类型` 替代。

**容器类型声明简化**：

数组和映射的声明语法已简化，省略了内部类型标记名称：

| 容器类型 | 声明写法           | 内部类型标记名称（编译器隐式处理） |
| :------- | :----------------- | :--------------------------------- |
| `数组`   | `数组<文本>`       | 隐式类型标记名称，开发者无感       |
| `映射`   | `映射<文本, 整数>` | 隐式类型标记名称，开发者无感       |

**类型标记名称的绑定机制**：

有名任意类型的类型标记名称是占位符，必须通过函数调用的实参来绑定具体类型。当编译器遇到以下代码时：

```智语言
取较大值(任意<甲: 整数|小数> 第一个, 任意<甲> 第二个) 任意<甲>
```

1. 在函数作用域中注册类型标记名称 `甲`，约束范围为 `整数|小数`
2. 函数调用 `取较大值(10, 20)` 时，实参 `10` 的类型 `整数` 绑定到 `甲`
3. 函数签名中所有 `甲` 替换为 `整数`，返回值类型确定为 `整数`

变量声明没有调用上下文，不存在"实参→形参"的绑定步骤，因此有名任意类型不能用于变量声明。

**接收 `任意<甲>` 返回值的方式**：

当调用返回 `任意<甲>` 的函数或方法时，接收方式取决于编译期能否确定 `甲` 的具体类型。

- **方式一：编译器可确定具体类型 → 直接用具体类型变量接收**。适用于自定义函数调用（实参已确定类型）和内置容器方法调用（容器类型标注已知）。例如 `整数 结果 = 取较大值(10, 20)`。
- **方式二：编译器无法确定具体类型 → 运行时类型判断**。适用于内置容器方法在通用上下文中被调用，编译器无法从声明处推断出容器的具体类型参数。此时使用 `类型()` 函数进行运行时分派。

**匿名任意类型初始化检查**：匿名任意类型的变量声明必须带初始值。若变量类型为匿名任意类型且声明时未赋值，报告编译错误：

```
第N行N列 | 错误：类型错误：匿名任意类型必须显式初始化
帮助：请为变量提供初始值，如：任意<整数|文本> 数据 = 42
```

##### 2.4.3 类型检查

类型检查发生在表达式求值类型和期望类型不一致时。检查规则覆盖：

**赋值检查**：

- 变量类型一旦确定，终身不变
- `整数` 可以隐式提升为 `小数`（唯一合法的隐式转换）
- 其他所有类型转换必须通过显式调用 `整数()`、`小数()`、`文本()` 等全局函数

**有名任意类型的使用限制**：

有名任意类型的类型标记名称只能在参数中声明、在返回值中引用。以下用法会在编译期报错：

```智语言
// ❌ 编译错误：有名任意类型不能用于变量声明
任意<甲: 整数|小数> 变量 = 42
```

编译器在语义分析阶段检查此规则。

**函数调用检查**：实参数量与类型必须匹配，返回值类型必须与声明一致。

**适配检查**：结构体声明 `适配 接口名` 时，检查结构体是否实现了接口声明的所有方法。

**空值安全检查**：空值不能参与运算，不能作为条件，使用 `任意<类型|空值>` 前必须检查非空。编译器在 if 分支内临时细化匿名任意类型的非空状态——在 `如果 变量 != 空值:` 的分支内，编译器将变量的类型临时细化为非空的 `类型`，允许直接作为该类型使用。

##### 2.4.4 类型转换实现

**隐式转换**：智语言中只有一种隐式转换：`整数 → 小数`。

**显式转换**：通过全局函数 `整数()`、`小数()`、`文本()` 进行。

在 HIR 中，隐式转换被表示为 `隐式转换` 节点，显式转换被表示为对全局函数的普通调用。

对于匿名任意类型，需要额外的运行时类型判断：

```智语言
安全除法(小数 被除数, 小数 除数) 任意<小数|文本>:
    如果 除数 == 0:
        返回 "除数不能为零"
    否则:
        返回 被除数 / 除数
    结束
结束
```

编译器在降级阶段为匿名任意类型的每个使用点插入类型标签检查指令。

##### 2.4.5 运算符重载实现

运算符重载在语义分析阶段解析。当遇到二元运算时，如果左侧是结构体类型，则在结构体的方法列表中查找与运算符对应的方法名（如 `+` 对应 `加法`），将运算重写为方法调用。对于 `==`，如果没有自定义 `等于` 方法，编译器自动生成逐字段比较的默认实现。

##### 2.4.6 编译期求值

编译期求值（Compile-Time Evaluation）在语义分析阶段对常量表达式进行求值。支持整数和浮点数的四则运算、比较运算、逻辑运算、字符串拼接和类型转换函数。编译期求值的结果直接替换原表达式，减少了运行时的计算开销。

**任意类型单态化策略**：

- **有名任意类型**：采用**编译期单态化**策略。编译器为每组具体类型参数生成一个特化版本。
- **匿名任意类型**：采用**类型擦除 + 运行时类型分派**策略。编译器生成一个通用版本，内部通过 `类型(值)` 运行时判断进行分派，避免代码膨胀。

#### 2.5 HIR 设计

高级中间表示（HIR）是语义分析阶段的输出产物。与 AST 不同，HIR 中的每个表达式和语句都携带了完整的类型信息，符号引用也解析为具体的符号表索引。

##### 2.5.1 HIR 与 AST 的区别

| 特性       | AST                        | HIR                                            |
| :--------- | :------------------------- | :--------------------------------------------- |
| 类型信息   | 无                         | 每个节点都标注类型                             |
| 符号引用   | 字符串名称                 | 指向符号表的具体索引                           |
| 任意类型   | 保留类型标记名称和约束范围 | 有名任意类型已单态化；匿名任意类型保留类型标签 |
| 语法糖     | 完整保留                   | 已展开为标准形式                               |
| 隐式转换   | 未处理                     | 已插入隐式转换节点                             |
| 运算符重载 | 保留运算符形式             | 已解析为方法调用                               |

##### 2.5.2 HIR 核心节点

**模块结构**：

```rust
struct Hir模块 {
    函数列表: Vec<Hir函数>,
    全局变量列表: Vec<Hir全局变量>,
    结构体定义列表: Vec<Hir结构体定义>,
    导入列表: Vec<导入声明>,
}

struct Hir函数 {
    名称: 字符串,
    形参列表: Vec<(字符串, 类型信息)>,
    返回类型: Option<类型信息>,
    函数体: Vec<Hir语句>,
    符号表引用: 作用域索引,
}
```

**语句与表达式**：

```rust
enum Hir语句 {
    变量声明 { 名称: 字符串, 初始值: Hir表达式, 类型: 类型信息, 是否可变: bool },
    赋值 { 目标: Hir表达式, 值: Hir表达式 },
    表达式语句(Hir表达式),
    条件语句 { 分支列表: Vec<(Hir表达式, Vec<Hir语句>)>, 否则分支: Option<Vec<Hir语句>> },
    循环语句 { 条件: Hir表达式, 循环体: Vec<Hir语句> },
    遍历语句 { 循环变量: Vec<字符串>, 容器: Hir表达式, 循环体: Vec<Hir语句> },
    返回语句(Option<Hir表达式>),
    异常控制 { 危险块: Vec<Hir语句>, 异常块: Option<Vec<Hir语句>>, 始终块: Option<Vec<Hir语句>> },
}

enum Hir表达式 {
    字面值(字面值, 类型信息),
    变量引用 { 符号索引: usize, 类型: 类型信息 },
    二元运算 { 左侧: Box<Hir表达式>, 运算符: 运算符, 右侧: Box<Hir表达式>, 类型: 类型信息 },
    调用 { 函数引用: usize, 实参列表: Vec<Hir表达式>, 类型: 类型信息 },
    成员访问 { 对象: Box<Hir表达式>, 成员索引: usize, 类型: 类型信息 },
    隐式转换 { 源表达式: Box<Hir表达式>, 目标类型: 类型信息 },
    匿名任意类型 { 类型标签: usize, 实际类型: 类型信息 },
}
```

异常控制节点中的 `始终块` 为可选字段。在降级转换阶段，始终块的执行语义被编码为基本块的跳转逻辑。

#### 2.6 HIR → LIR 转换

降级是前端流水线的最后一步，将 HIR 转换为 LIR，同时锁定所有与运行行为相关的语义。

##### 2.6.1 降级的主要任务

1. **控制流结构化**：将 HIR 中的控制流转换为由基本块构成的控制流图。对于四段式异常控制（`捕获-异常-始终-结束`），降级时生成四个基本块区域，确保无论走哪条路径，始终块总是在控制流离开异常控制结构之前执行。具体语义：
   - 正常执行：捕获块末尾 → 始终块 → 结束之后
   - 异常被处理：异常块末尾 → 始终块 → 结束之后
   - 异常被重新抛出：裸 `抛出` → 始终块 → 异常向上传播
   - 无异常块且异常发生：异常发生点 → 始终块 → 异常向上传播

2. **类型擦除**：将 HIR 中丰富的类型信息降级为 LIR 中的具体数据类型。有名任意类型已单态化完成。

3. **隐式转换显式化**：HIR 中的隐式转换节点被显式替换为对应的 LIR 类型转换指令。

4. **运算符重载解析**：正常情况下，语义分析已将其转换为方法调用，降级只需翻译调用指令。

5. **空值检查插入**：对可能为空值的匿名任意类型操作，自动插入显式的空值检查指令。

6. **初始化与清理调用**：在结构体实例创建处插入 `初始化` 调用，在实例离开作用域或 GC 回收前插入 `清理` 调用。

7. **索引基准固化**：所有数组、映射、文本的索引操作数在 LIR 中均标记为 1-based。后端实现必须据此进行 `索引 - 1` 的转换。查找类指令的"未找到"返回值统一设为 0。

8. **匿名任意类型的运行时类型标签**：对于匿名任意类型，降级时插入类型标签检查指令。

9. **COW（写时复制）语义降级**：赋值操作 `b = a` 转换为**增加引用计数**指令。真正的复制推迟到写操作发生时才执行。COW 的具体实现由统一运行时提供，降级时只需生成对应的运行时调用指令。

10. **逃逸分析与独占标记**：降级时对复合类型进行逃逸分析。如果创建后只在一个函数内操作，从未传给其他函数或赋值给全局变量，标记为"独占"。独占对象的写入操作生成优化的存储指令，跳过 COW 检查。

##### 2.6.2 基本块与三地址码

LIR 以函数为单位组织。每个 LIR 函数由一系列基本块构成，基本块之间通过跳转指令连接形成控制流图。

**基本块规则**：

- 基本块的第一条指令是其唯一入口。
- 基本块的最后一条指令是终止指令（跳转、条件跳转、返回、切换、抛出异常）。
- 基本块内部不允许包含任何跳转指令。

**三地址码格式**：

```
结果 = 操作码 操作数1, 操作数2
```

每条指令最多包含三个地址，操作数可以是立即数、局部变量引用、全局变量引用或常量池索引。

#### 2.7 LIR 设计

LIR 处于前端与双后端之间，是所有后端实现的唯一输入源。

##### 2.7.1 LIR 定位

- **语义的唯一法律**：程序"应该怎么执行"，由 LIR 的语义规范说了算。
- **前后端的唯一接口**：前端产生的 LIR 模块是后端唯一需要理解的数据结构。
- **可持久化的执行契约**：LIR 模块可被序列化为字节流。

##### 2.7.2 LIR 数据结构

```rust
struct Lir模块 {
    模块名: 字符串,
    函数列表: Vec<Lir函数>,
    全局变量列表: Vec<Lir全局变量>,
    结构体定义列表: Vec<Lir结构体定义>,
    类型表: Vec<Lir类型>,
    常量池: Vec<常量值>,
    调试信息: 调试信息,
    入口函数索引: Option<usize>,
}

struct Lir函数 {
    名称: 字符串,
    形参列表: Vec<(字符串, Lir类型)>,
    返回类型: Lir类型,
    基本块列表: Vec<基本块>,
    局部变量表: Vec<Lir类型>,
    调试信息: 函数调试信息,
}

struct 基本块 {
    标识符: usize,
    指令列表: Vec<三地址码>,
    终止指令: 终止指令,
}

struct 三地址码 {
    结果: 操作数,
    操作码: 操作码,
    操作数1: 操作数,
    操作数2: Option<操作数>,
    调试位置: Option<源码位置>,
}
```

**LIR 类型**：LIR 类型是对智语言类型的低阶映射。匿名任意类型在 LIR 中表示为带标签的结构体（包含类型标签字段和数据字段）。有名任意类型已完成单态化，LIR 中不包含类型标记名称。

##### 2.7.3 LIR 指令集

LIR 指令集按功能分为六大类。完整指令集速查表见附录 B，此处概述分类：

- **控制流指令**：跳转、条件跳转、返回、切换、抛出异常
- **数据操作指令**：算术运算（含 `整除`）、比较、位运算、逻辑运算
- **内存指令**：加载、存储、数组/映射操作、字段访问。其中数组和映射操作的索引操作数均为 1-based。写入前执行 COW 检查。新增指令：`引用计数增加`、`引用计数减少`
- **类型转换指令**：数值类型互转、文本与数值互转
- **运行时指令**：函数调用、结构体创建、通道操作、任务调度、空值检查、匿名任意类型标签读取。所有运行时指令最终调用统一运行时的对应 API
- **调试指令**：调试位置标记、调试断点

**空值检查指令**：

```
空值检查 值
```

检查指定值是否为空值，如果是则抛出运行时异常。

##### 2.7.4 LIR 语义规范

**索引与查找返回值约定**：

> **所有数组、映射、文本的索引操作数均为 1-based。** 后端在访问底层内存时需进行 `索引 - 1` 的转换。越界检查条件为 `索引 < 1 或 索引 > 长度`。查找类指令（如 `查找索引`、`文本查找`）在未找到目标时返回 0。

**整数运算**：64 位有符号整数，溢出采用回绕（wrapping）语义，整数除零（`/`、`%%`、`%`）统一抛出运行时异常。
**小数运算**：IEEE 754 双精度浮点，除零产生特殊值（±∞、NaN）而不抛出异常。
**文本操作**：基于 Unicode 码点计数，字符位置从 1 开始。
**空值语义**：空值是独立类型，必须显式检查后才能用作非空操作。
**异常处理**：四段式结构（`捕获-异常-始终-结束`），始终块无论异常是否发生都会在控制流离开异常结构前执行。
**COW 语义**：赋值时增加引用计数而非深拷贝。写操作时若引用计数 > 1 则先深拷贝。独占对象跳过 COW 检查。
**任意类型语义**：有名任意类型已单态化。匿名任意类型的值表示为"实际数据 + 类型标签"。
**统一运行时语义**：所有堆操作、系统调用和异常处理最终调用统一运行时的同一套 API。

### 第三部分 后端设计

后端设计涵盖智语言程序在通过前端处理生成 LIR 之后的所有执行路径。本章分别描述解释器（解释模式）和编译器（编译模式）的具体实现，以及双模式共享的运行时组件。


#### 3.1 解释器（解释模式）

##### 3.1.1 解释模式定位

解释模式是智语言双模式架构中的即时执行路径，对应命令 `智语言 运行`。它的核心价值在于：**开发者修改源代码后，无需等待构建，即可立即看到程序运行结果**。

| 维度         | 解释模式                            | 编译模式                                  |
| :----------- | :---------------------------------- | :---------------------------------------- |
| 启动方式     | 源码 → 前端 → LIR → 字节码 → 虚拟机 | 源码 → 前端 → LIR → Cranelift IR → 机器码 |
| 首次启动耗时 | 前端解析 + 字节码生成 + 虚拟机启动  | 前端解析 + Cranelift 编译 + 链接          |
| 二次启动耗时 | 命中缓存，直接加载字节码 → 虚拟机   | 直接运行可执行文件                        |
| 运行时性能   | 解释执行，约为原生速度的 5%–15%     | 接近原生速度                              |
| 调试体验     | 内置命令行调试器                    | DWARF + 外部调试器                        |
| 适用场景     | 学习、原型开发、脚本任务、调试      | 生产部署、性能敏感应用、分发              |

##### 3.1.2 字节码设计

字节码是 LIR 到虚拟机之间的桥梁。它由 LIR 指令序列经过直接映射和部分优化后生成，采用紧凑的二进制格式。

**设计原则**：

- **与 LIR 一一对应**：每一条 LIR 指令都能在字节码指令集中找到对应项。
- **紧凑性优先**：操作码采用单字节编码。
- **自描述性**：字节码文件包含常量池、类型表、调试信息等元数据。
- **可扩展**：操作码空间预留了扩展区。

字节码文件包含文件头（魔数、版本号）、模块名段、常量池段、函数表段、调试信息段和代码段。详细格式见附录 C。

**LIR 到字节码的映射**：

LIR 指令与字节码指令基本一一对应。复合类型的写入操作（如 `数组存储`）在生成字节码时，自动插入引用计数检查和 COW 拷贝逻辑。字节码指令格式采用显式寄存器操作数编码（操作码 + 目标寄存器 + 源寄存器1 + 源寄存器2），与 LIR 三地址码直接映射。

##### 3.1.3 字节码缓存

缓存键基于**内容哈希**（SHA256）而非文件修改时间，确保在任何场景下缓存一致性可靠。

```rust
struct 缓存键 {
    源文件哈希: 字符串,
    依赖模块哈希列表: Vec<字符串>,
    工具链版本: 字符串,
}
```

**缓存文件位置**：

- **项目内执行**：字节码缓存放在项目 `产出/字节码文件/` 目录下（由 `项目.配置` 中的 `源码字节码文件` 字段指定）
- **项目外单文件执行**：字节码放在全局目录 `~/.智语言/产出/字节码文件/` 下

**依赖图与增量失效**：

当模块 A 导入了模块 B，而模块 B 的源文件发生变化时，模块 A 的缓存也会失效。依赖图在首次编译时建立，当任意模块的哈希发生变化时，缓存管理器递归地失效所有直接和间接依赖该模块的缓存条目。

##### 3.1.4 寄存器虚拟机

寄存器虚拟机是解释模式的核心执行引擎。它读取字节码指令，逐条解释执行，维护虚拟寄存器文件和调用帧栈。

**与 LIR 的天然匹配**：

LIR 的三地址码格式（`结果 = 操作码 左, 右`）可以直接映射为寄存器指令——LIR 的虚拟寄存器映射为虚拟机的虚拟寄存器，不需要额外的栈操作转换。

**虚拟机架构**：

```
┌──────────────────────────────────────┐
│              虚拟机实例               │
├──────────────────────────────────────┤
│  字节码存储                         │
│  - 函数表: Vec<函数元数据>          │
│  - 代码段: Vec<u8>                 │
│  - 常量池: Vec<运行时值>            │
│  - 类型表: Vec<类型信息>            │
├──────────────────────────────────────┤
│  执行状态                           │
│  - 指令指针: usize                  │
│  - 虚拟寄存器文件: Vec<运行时值>     │
│  - 调用帧栈: Vec<调用帧>            │
│  - 全局变量: Vec<运行时值>          │
├──────────────────────────────────────┤
│  运行时组件（共享）                  │
│  - 统一运行时 (值/堆/GC/COW/并发)   │
│  - 调试器接口                       │
└──────────────────────────────────────┘
```

**职责边界**：

- **虚拟机管理**：虚拟寄存器文件、调用帧栈、指令指针、字节码存储
- **统一运行时管理**：全局堆（GC 管理）、并发资源表（通道/任务句柄/终止器）、系统调用、异常对象创建

虚拟寄存器中存储的是 `运行时值`（32 字节），与统一运行时共享值表示。堆对象（句柄指向）由统一运行时管理，虚拟机通过 `运行时值` 的句柄字段引用。

**调用帧**：

```rust
struct 调用帧 {
    函数索引: usize,
    返回地址: usize,
    保存的寄存器: Vec<运行时值>,  // 调用者寄存器文件的保存副本
    异常处理表: Vec<异常处理器>,
}
```

**主执行循环**：

```
执行(入口函数索引):
    创建调用帧(入口函数索引, 返回地址=None)
    分配虚拟寄存器文件
    压入调用帧栈

    当 调用帧栈 不为空:
        当前帧 = 调用帧栈.栈顶()
        操作码 = 读取字节(当前帧.指令指针)

        如果 操作码 是调试断点 且 调试器已附着:
            进入调试模式()

        根据 操作码 执行对应操作:
            情况 0x00: 执行跳转(操作数)
            情况 0x01: 执行条件跳转(操作数)
            情况 0x02: 执行返回(操作数)
            情况 0x40: r_目标 = r_左 + r_右  // 寄存器操作
            // ... 其他操作码

        当前帧.指令指针 += 当前指令长度
```

**COW（写时复制）实现**：

当执行复合类型的写入指令时，虚拟机调用统一运行时的 `堆_写入前复制()` 函数。该函数检查引用计数，如果数据被多处引用则先深拷贝一份再进行写入。逃逸分析标记为独占的对象跳过 COW 检查，直接写入。

**1-based 索引处理**：虚拟机在执行数组、映射、文本相关指令时，统一进行 1-based 到内部实现的转换。越界检查条件为 `索引 < 1 或 索引 > 长度`。查找类指令在未找到时返回 0。

##### 3.1.5 调试器（解释模式）

解释模式内建一个命令行交互式调试器，通过 `智语言 运行 --调试` 启动。

| 命令            | 简写       | 功能                                   |
| :-------------- | :--------- | :------------------------------------- |
| `断点 行号`     | `b 行号`   | 在指定行设置断点                       |
| `断点 函数名`   | `b 函数名` | 在函数入口设置断点                     |
| `删除断点 编号` | `d 编号`   | 删除指定编号的断点                     |
| `断点列表`      | `bl`       | 列出所有断点                           |
| `继续`          | `c`        | 继续执行直到下一个断点                 |
| `单步`          | `s`        | 执行当前行（进入函数）                 |
| `下一步`        | `n`        | 执行当前行（跳过函数）                 |
| `查看 变量名`   | `p 变量名` | 打印变量当前值                         |
| `查看局部`      | `pl`       | 打印所有局部变量（读取虚拟寄存器文件） |
| `调用栈`        | `bt`       | 显示调用栈回溯                         |
| `退出`          | `q`        | 终止程序并退出调试器                   |

##### 3.1.6 参数传递实现

**传值实现（默认）**：将实参的 `运行时值` 直接复制到被调用函数的虚拟寄存器中。对于复合类型，复制的是句柄，同时增加全局堆中对应对象的引用计数。COW 机制保证写入时触发深拷贝。

**传引用实现（显式）**：当形参标记为 `传引用` 时，解释器创建 `运行时值::局部引用(索引)`，将实参在调用者虚拟寄存器文件中的索引编码到 `运行时值` 中（标签=5，整数字段存储索引）。被调用函数通过 `间接加载` 和 `间接存储` 指令操作该局部引用。

##### 3.1.7 交互式控制台

启动方式为 `智语言 交互`。逐条输入智语言语句并立即执行，自动维护变量上下文，支持多行输入。在统一运行时架构下，控制台的变量上下文直接存储 `运行时值`，与主解释器完全共享运行时状态。


#### 3.2 编译器（编译模式）

##### 3.2.1 编译模式定位

编译模式将智语言源代码编译为独立的原生可执行文件，对应命令 `智语言 构建`。

```bash
智语言 构建 主程序.智                # 默认：speed 优化
智语言 构建 --最快编译 主程序.智      # none 优化
智语言 构建 --最小编译 主程序.智      # speed_and_size 优化
```

##### 3.2.2 LIR → Cranelift IR

**类型映射**：

| LIR 类型       | Cranelift 类型  | 说明                               |
| :------------- | :-------------- | :--------------------------------- |
| `整数64`       | `i64`           | 64 位有符号整数                    |
| `小数64`       | `f64`           | IEEE 754 双精度浮点                |
| `文本`         | 指针+长度结构体 | 长度（i64）+ 指向 UTF-8 数据的指针 |
| `布尔`         | `i8`            | 1 字节布尔值                       |
| `空值`         | 空结构体        | 零大小类型                         |
| `匿名任意类型` | 带标签的结构体  | 包含类型标签字段和数据字段         |

在统一运行时架构下，所有复合类型在 Cranelift IR 中均表示为指向运行时全局堆的句柄（64 位整数）。

**核心指令翻译示例**：

```
LIR: 结果 = 加法 左操作数, 右操作数
→ Cranelift IR: 结果 = iadd 左, 右     (整数)

LIR: 结果 = 整除 左, 右
→ Cranelift IR: 结果 = sdiv 左, 右     (整数整除，除零抛异常)

LIR: 条件跳转 条件, 真分支, 假分支
→ Cranelift IR: brnz 条件, 真分支; jump 假分支
```

**空值检查翻译**：

`空值检查` LIR 指令翻译为 Cranelift IR 的条件分支：检查值的标签字段是否为空值标签，如果是则调用 `智语言_抛出异常()`，否则继续执行。

**1-based 索引处理**：在生成数组访问的 Cranelift IR 时，显式插入 `用户索引 - 1` 的调整指令。越界检查使用转换前的 1-based 条件：`索引 < 1 或 索引 > 长度`。查找类指令在翻译时确保未找到返回 0。

**编译期类型细化的代码生成**：当语义分析器在 if 分支内确定了匿名任意类型的非空状态后，生成的 LIR 中该分支内的变量引用不再包含 `空值检查` 指令。编译器直接生成对应具体类型的操作代码，无需运行时检查。

##### 3.2.3 优化管线

| 命令标志              | Cranelift 优化级别 | 说明                                             |
| :-------------------- | :----------------- | :----------------------------------------------- |
| `智语言 构建`（默认） | `speed`            | 开启寄存器分配、指令调度、基本块重排、常量折叠等 |
| `--最快编译`          | `none`             | 不做优化，构建速度最快                           |
| `--最小编译`          | `speed_and_size`   | 速度优化基础上额外关注代码体积                   |

##### 3.2.4 目标文件生成与链接

Cranelift 直接将优化后的 IR 转换为目标平台的机器码。所有编译出的可执行文件都需要链接统一运行时库（包含值表示、全局堆管理、COW 实现、GC、异常处理、系统调用和并发原语）。标准库也以静态库形式链接。

##### 3.2.5 多平台支持

支持 Linux、macOS、Windows 三大平台，x86-64 和 ARM64 架构。可通过 `--目标平台` 参数手动指定交叉编译目标。

##### 3.2.6 调试信息生成（DWARF）

编译模式通过 `智语言 构建 --调试` 生成 DWARF 调试信息，配合 gdb、lldb 等标准调试器使用。发布优化（`speed` 级别）与调试信息生成存在冲突，`--调试` 模式下默认使用 `none` 优化级别。

##### 3.2.7 参数传递实现

**传值实现（默认）**：对于基本类型，Cranelift 按值传递参数。对于复合类型，编译器传递句柄，同时生成对 `智语言_引用计数增加` 的调用。

**传引用实现（显式）**：编译器直接传递实参的地址（指针）。被调用函数通过该指针直接作用于调用者的原变量。


#### 3.3 任务调度

智语言的并发模型基于统一运行时提供的任务调度机制。

```rust
struct 任务管理器 {
    任务表: HashMap<任务标识, 任务>,
    下一个标识: AtomicU64,
}

struct 任务 {
    标识: u64,
    状态: 任务状态,
    结果: Option<运行时值>,
    等待队列: Vec<任务标识>,
}

enum 任务状态 {
    运行中,
    已完成(运行时值),
    异常(异常错误),
}
```

**任务启动**：当执行 `并发.启动任务(操作)` 时，运行时创建一个新任务并分配唯一标识。

**任务等待**：`任务.等待结果()` 阻塞当前执行单元，直到目标任务完成。

**批量等待**：`并发.批量等待(任务数组)` 阻塞直到所有任务完成。带超时的版本在超时后返回已完成的结果。


#### 3.4 通道

通道是任务之间安全传递数据的通信载体，由统一运行时提供。

```rust
struct 通道 {
    缓冲区: VecDeque<运行时值>,
    容量: usize,
    是否关闭: bool,
    发送等待: VecDeque<任务标识>,
    接收等待: VecDeque<任务标识>,
}
```

**通道操作**：

- **发送**：如果缓冲区未满，将数据加入缓冲区并唤醒一个等待的接收者。如果缓冲区已满，阻塞当前任务。向已关闭通道发送将抛出运行时异常。
- **接收**：如果缓冲区非空，取出数据。如果通道已关闭且缓冲区为空，返回空值。如果通道为空且未关闭，阻塞当前任务。
- **关闭**：标记通道为已关闭，唤醒所有等待者。


#### 3.5 垃圾回收

##### 3.5.1 设计原则

**自动化**：开发者不感知 GC 的存在。**安全**：不会出现悬挂指针或重复释放。**与 COW 的协调**：引用计数用于 COW 逻辑，GC 负责最终的内存回收。

##### 3.5.2 堆对象表示

```rust
struct 堆对象头 {
    标记位: bool,
    类型标识: usize,
    对象大小: usize,
    引用计数: usize,        // COW 引用计数
    下一个: Option<*mut 堆对象头>,
}
```

##### 3.5.3 标记-清除算法

**标记阶段**：从根集出发，递归标记所有可达对象。根集通过统一回调接口收集，包括所有全局变量、当前所有任务的调用栈中的虚拟寄存器、通道缓冲区数据。

**清除阶段**：遍历堆对象链表，回收标记位为 `false` 且引用计数为 0 的对象，将存活对象的标记位重置为 `false`。

##### 3.5.4 触发时机

- **内存阈值**：当堆分配的总字节数超过阈值时自动触发。
- **显式调度点**：当所有任务线程都阻塞在通道/等待操作时触发。
- **引用计数归零**：当 COW 引用计数归零时，对象被标记为"可回收"，由下一次 GC 统一回收（避免在减引用操作中直接释放内存的并发安全问题）。

##### 3.5.5 GC 与 FFI 的交互

在 FFI 调用期间，GC 不会触发。FFI 调用返回后，GC 恢复正常调度。


#### 3.6 生命周期管理

##### 3.6.1 初始化调用时机

当执行 LIR 中的 `创建结构体` 指令时，运行时在全局堆上分配结构体内存，然后自动调用该结构体定义的 `初始化` 方法。初始化方法没有自己的参数列表，直接复用结构体的全局参数。不能写返回类型，不能重载。可使用无返回值的 `返回` 提前退出。

##### 3.6.2 清理调用时机

- **堆分配的结构体实例**：GC 回收前调用清理方法。
- **栈分配的结构体实例**（编译模式优化）：离开作用域时立即调用。
- **程序退出**：遍历所有仍存活的结构体实例，依次调用清理方法。

##### 3.6.3 与异常处理的交互

当异常穿过包含结构体实例的作用域时，运行时在栈展开过程中调用该实例的清理方法。

##### 3.6.4 执行保证

运行时不保证清理方法一定被调用（如程序异常终止时）。清理方法不应包含对程序正确性至关重要的逻辑。


#### 3.7 闭包实现

##### 3.7.1 环境捕获

当语义分析器遇到匿名函数或函数值赋值时，分析函数体内引用的外部变量。这些自由变量构成闭包的"环境"。

前端降级转换阶段为每个闭包生成一个隐式的环境结构体。对于值捕获（默认），将变量的 `运行时值` 复制到环境结构体中——复合类型仅增加引用计数，与函数传参语义一致。对于传引用捕获，将变量的局部引用存入环境结构体。

闭包内部修改捕获的复合类型数据时，COW 机制将确保闭包拥有独立副本，不污染外部变量。

##### 3.7.2 闭包类型表示

闭包在统一运行时中以"函数指针 + 环境句柄"的形式表示。函数指针指向闭包的实际执行代码，环境句柄指向全局堆上分配的环境结构体。

##### 3.7.3 闭包与 GC 的交互

闭包的环境结构体分配在 GC 管理的全局堆上。当闭包不再被任何变量引用时，其环境结构体由 GC 在下次回收时自动释放。


#### 3.8 统一运行时

##### 3.8.1 设计原则

- **单一值表示**：统一使用 `运行时值`（32 字节 `#[repr(C)]` 扁平结构体）
- **单一全局堆**：所有复合类型统一存储在全局堆中
- **单一 GC 实现**：标记-清除 GC 由运行时统一实现
- **单一 COW 实现**：写时复制逻辑由运行时的 `堆_写入前复制()` 统一实现
- **双模式接口**：解释器直接通过 Rust 函数调用，编译器通过 C ABI 调用

##### 3.8.2 统一值表示

```rust
#[repr(C)]
pub struct 运行时值 {
    pub 标签: u64,      // 0=空值, 1=整数, 2=小数, 3=布尔, 4=句柄, 5=局部引用, 6=并发句柄, 7=运行时句柄
    pub 整数: i64,      // 标签为 1/3/5 时使用
    pub 小数: f64,      // 标签为 2 时使用
    pub 句柄: u64,      // 标签为 4/6/7 时使用
}
```

**局部引用（标签=5）**：用于传引用参数的实现，整数字段存储虚拟寄存器文件中对应值的索引。

##### 3.8.3 统一全局堆

```rust
struct 堆槽位 {
    数据: 堆数据,
    共享计数: u32,    // COW 引用计数
    gc标记: bool,     // GC 标记位
}

enum 堆数据 {
    文本(String),
    数组(Vec<运行时值>),
    映射(Vec<(堆键, 运行时值)>),
    结构体 { 类型索引: usize, 字段值: Vec<运行时值> },
    闭包 { 函数索引: usize, 捕获变量: Vec<运行时值> },
}
```

##### 3.8.4 COW 写时复制

```rust
pub fn 堆_写入前复制(句柄: u64) -> u64 {
    let 槽位 = 全局堆读取(句柄);
    if 槽位.共享计数 <= 1 {
        return 句柄;  // 独占，无需复制
    }
    let 副本 = 槽位.数据.clone();
    堆_减少引用(句柄);
    堆_分配_槽位(副本, 1)  // 新对象共享计数=1
}
```

##### 3.8.5 统一 GC

```rust
pub fn 执行标记清除(根集回调: Box<dyn Fn() -> Vec<运行时值>>) -> usize
```

- **解释器模式**：根集回调遍历虚拟机的调用帧栈、虚拟寄存器文件和全局变量表
- **编译模式**：根集回调通过编译器生成的栈映射收集根集

##### 3.8.6 并发资源统一管理

```rust
struct 并发资源表 {
    资源列表: Vec<并发资源>,
    空闲列表: Vec<usize>,
}

enum 并发资源 {
    通道(通道),
    任务句柄(任务句柄),
    终止器(终止器),
}
```

##### 3.8.7 双模式接口

- **Rust ABI**（解释器使用）：直接函数调用
- **C ABI**（编译器使用）：通过 `#[export_name]` 导出，如 `智语言_堆操作`、`智语言_系统调用`

两层接口调用同一套实现，确保双模式的行为完全一致。

### 第四部分 基础能力设计

基础能力设计涵盖贯穿解释器和编译器后端的共享支撑模块。这些模块不是核心编译流水线的一部分，但为工具链提供了诊断、互操作、安全、测试、性能和质量保障等必不可少的能力。


#### 4.1 错误报告规范

##### 4.1.1 错误级别与类型

错误分为两个严重级别：

| 级别     | 标识   | 含义               | 对解释器影响   | 对编译器影响       |
| :------- | :----- | :----------------- | :------------- | :----------------- |
| **错误** | `错误` | 必须修复的严重问题 | 终止执行       | 终止编译           |
| **警告** | `警告` | 建议修复的问题     | 显示警告后继续 | 显示警告后继续生成 |

所有错误类型使用中文名称：

| 错误类型   | 严重级别 | 触发阶段          | 典型场景                                         |
| :--------- | :------: | :---------------- | :----------------------------------------------- |
| 语法错误   |   错误   | 词法/语法分析     | 缺少关键字、括号不匹配、全角标点误用、注释未闭合 |
| 语义错误   |   错误   | 语义分析          | 重复声明、无效操作、作用域错误                   |
| 类型错误   |   错误   | 语义分析          | 类型不匹配、有名任意类型用于变量声明             |
| 参数错误   |   错误   | 语义分析          | 参数数量错误、缺少必填参数、传引用参数有默认值   |
| 命名错误   |   错误   | 词法分析/文件加载 | 标识符或路径含非法字符                           |
| 网络错误   |   错误   | 运行时            | 连接失败、超时                                   |
| 并发错误   |   错误   | 运行时            | 通道关闭后发送、死锁检测                         |
| 资源错误   |   错误   | 运行时            | 文件不存在、内存不足                             |
| 运行时错误 |   错误   | 运行时            | 除零、数组越界、空值引用                         |
| 内部错误   |   错误   | 工具链自身        | 编译器内部断言失败、代码生成异常                 |
| 代码建议   |   警告   | 语义分析          | 未使用的变量、已弃用的 API                       |

> 内部错误末尾附加："请向官方反馈此问题，以便我们改进智语言。"

#### 4.2 外部函数接口（FFI）

##### 4.2.1 C ABI 兼容

智语言的 FFI 设计遵循三条原则：简单易用、类型安全、最小侵入。选择 C ABI 是因为它是业界最广泛支持的跨语言调用标准。

##### 4.2.2 调用外部函数

使用 `外部:` 块声明外部函数，`关联` 绑定 C 符号名：

```智语言
外部:
    ["sqlite3" 别名 "数据库"]
    ["打开数据库" 关联 "数据库.sqlite3_open"]
打开数据库(文本 路径, 输出 整数 句柄) 整数:
结束
结束
```

**类型映射**：

| 智语言类型       | C 类型                    | 大小      |
| :--------------- | :------------------------ | :-------- |
| `整数`           | `int64_t`                 | 8 字节    |
| `小数`           | `double`                  | 8 字节    |
| `文本`（参数）   | `const char*` + `size_t`  | 指针+长度 |
| `文本`（返回值） | `char*`（调用者负责释放） | 指针      |
| `布尔`           | `uint8_t`                 | 1 字节    |

##### 4.2.3 导出函数供外部调用

使用 `导出:` 块将智语言函数暴露为 C ABI 符号：

```智语言
导出:
    ["加法" 关联 "math_add"]
加法(整数 甲, 整数 乙) 整数:
    返回 甲 + 乙
结束
结束
```

编译模式通过 `--静态` 控制生成静态库还是动态库（默认动态库）。导出产物独立存放在 `产出/导出文件/` 下。


#### 4.3 安全模型

##### 4.3.1 内存安全

所有复合类型分配在统一运行时的全局堆上，由 GC 统一管理。采用 COW 策略实现值语义——赋值时仅增加引用计数，写操作时才触发深拷贝。

##### 4.3.2 类型安全

编译期类型检查覆盖变量赋值、函数调用、运算符、成员访问、适配检查、有名任意类型限制等全部场景。有名任意类型通过编译期单态化实现，匿名任意类型采用类型擦除策略。

##### 4.3.3 空值安全

空值是独立类型，不能参与任何运算。编译器追踪匿名任意类型变量在控制流中的"空值状态"——在 `如果 变量 != 空值:` 的分支内，变量的类型被临时细化为非空的类型，允许直接使用。

##### 4.3.4 模块隔离

公开（默认）和私有（`私有` 关键字）两个可见性级别。可见性检查在语义分析阶段完成。

##### 4.3.5 外部调用安全

FFI 调用期间 GC 不会触发，调用返回后恢复正常调度。


#### 4.4 测试与一致性保证

##### 4.4.1 测试框架

测试函数是名称以 `测试` 开头的普通函数。测试运行器自动发现并执行所有符合命名约定的函数。

```bash
智语言 测试                          # 运行所有测试
智语言 测试 --过滤 加法              # 只运行名称中包含"加法"的测试
智语言 测试 --超时 10              # 设定单测试函数超时秒数（0=关闭，默认 60）
```

##### 4.4.2 单元测试与集成测试

单元测试验证单个函数或方法，集成测试验证多个模块的协作。

##### 4.4.3 一致性测试（解释器 vs 编译器）

验证同一份源码在解释器和编译器下产生完全相同的运行结果。按语言特性分类组织，覆盖全部语言特性。

##### 4.4.4 标准库自举验证

使用智语言自身的测试框架，对标准库的每个模块、每个函数进行完整的功能验证，在解释器和编译器两种模式下分别运行。

##### 4.4.5 CI 双重验证

每次代码提交触发 CI 流水线：格式检查 → 构建 → 单元测试 → 解释器测试 → 编译器测试 → 结果比较。差异为零才算通过。


#### 4.5 性能基准

##### 4.5.1 基准测试套件

按类别组织：数值计算、文本处理、数据结构、任意类型、并发、启动时间。

```bash
智语言 基准                          # 运行所有基准测试
智语言 基准 --重复 10                # 每个测试重复 10 次取平均值
```

##### 4.5.2 解释器 vs 编译器性能对比

**COW 专项性能数据**：

| 操作               | COW 实现 | 旧 Clone 实现 | 提升倍数 |
| :----------------- | :------: | :-----------: | :------: |
| 赋值大数组         |  ~20ns   |     ~50μs     |  ~2500x  |
| 传参大数组         |  ~20ns   |     ~50μs     |  ~2500x  |
| 写数组元素（首次） |   ~3μs   |    ~120ns     |  0.04x   |
| 写数组元素（后续） |  ~120ns  |    ~120ns     |    1x    |

首次写入触发 COW 深拷贝，后续写入为 O(1)。在 90% 的真实场景中 COW 从不触发。

##### 4.5.3 常见优化模式

避免不必要的堆分配、利用 COW 减少拷贝、利用编译器的逃逸分析、选择合适的容器操作、合理控制任务粒度。

##### 4.5.4 性能回归检测

CI 流水线中自动检测性能退化。执行时间增加超过 5% 为警告，超过 15% 为严重。

#### 4.7 异常处理机制

##### 4.7.1 异常抛出与捕获语义

四段式结构 `捕获: ... 异常: ... 始终: ... 结束`。语义规则：

- 异常在捕获块内被触发且存在异常块 → 执行异常块 → 始终块 → 结束之后
- 异常块中使用裸 `抛出` → 始终块在异常传播前执行
- 异常未被任何异常块捕获 → 程序终止

##### 4.7.2 栈展开策略

从异常抛出的当前函数开始，沿调用栈向上回溯。每帧检查异常处理表，退出作用域的结构体实例触发 `清理` 方法。

##### 4.7.3 异常对象结构

```rust
struct 异常错误 {
    描述: 字符串,
    类型: 字符串,
    位置: 源码位置,
    堆栈: 字符串,
}
```

`异常错误()` 函数仅限于在 `异常:` 块内部调用。

##### 4.7.4 解释器实现

1. 虚拟机执行 `抛出` 指令，调用统一运行时创建异常对象。
2. 从当前调用帧向上遍历调用帧栈，查找匹配的异常处理块。
3. 弹出中间调用帧，触发结构体清理。
4. 找到处理块后，将异常对象存入指定虚拟寄存器，跳转到异常块执行。
5. 始终块在异常块执行完毕后自动执行。
6. 未找到处理块则打印未捕获异常信息，终止程序。

##### 4.7.5 编译器实现

- **抛出**：调用 `智语言_抛出异常` 运行时函数。
- **捕获**：在捕获块入口调用 `智语言_异常推入处理块`，出口调用 `智语言_异常弹出处理块`。
- **始终块**：捕获块正常出口和异常块末尾都生成跳转到始终块的指令。
- **栈展开**：编译器在每个可能抛出异常的函数调用后插入清理代码。

工程体系设计涵盖标准库、模块系统、库管理器、项目工程和最佳实践五个方面，它们共同构成智语言从代码编写到项目交付的完整工程化支撑体系。


#### 5.1 标准库

标准库是智语言官方提供的功能模块集合，涵盖数学计算、文件操作、网络通信、时间处理、系统交互、数据处理和并发编程七大领域。

##### 5.1.1 标准库设计原则

**用智语言编写 API 层，底层通过统一运行时调用系统能力**

标准库的 API 层使用智语言自身编写，编译为 LIR 模块供两种模式共享。底层实现通过统一运行时调用系统能力——包括 Rust 标准库（如网络模块的 `std::net`）、C 标准库（如数学模块的 `libm`）和操作系统 API。

这种设计保证了标准库的行为在两种模式下完全一致，同时充分利用了 Rust 生态和操作系统提供的成熟高性能底层能力。API 层能编译通过并正确运行，本身也证明了解释器和编译器的正确性。

#### 5.2 模块系统

##### 5.2.1 模块路径解析

每个 `.智` 文件对应一个模块，模块名自动取自文件名（不含后缀）。编译器维护一个 `模块注册表`，记录所有已加载模块的路径、源码和编译状态。

模块路径解析算法：

1. 根据 `导入` 语句中的模块名，按以下顺序查找：
   - 项目级库目录（`项目目录/库/`）
   - 全局级库目录（`~/.智语言/库/`）
   - 标准库目录（`安装路径/智语言工具包<版本号>/标准库/源码/`）
2. 支持嵌套引用，如 `导入 数学.几何.圆形` 对应路径 `数学/几何/圆形.智`。
3. 已解析的模块会被缓存，避免重复加载。
4. 在模块路径解析过程中，对文件路径中的每一段进行字符合法性检查。目录名和文件名只能使用中文简繁汉字、半角数字、半角下划线、半角点。不符合规范的文件名在加载前被拒绝，编译器报告错误。

**模块导入不支持批量导入（`*`）**，必须显式声明导入的模块名。

##### 5.2.2 导入语义

- **基本导入**（`导入 模块名`）：调用时需加模块名前缀。
- **展开导入**（`导入 模块名 展开`）：模块内的公开符号直接提升到当前作用域。
- **别名导入**（`导入 模块名 别名 名称`）：以别名注册模块。`别名` 是模块系统的关键字。
- **批量导入**：不支持使用 `*` 进行批量导入。

##### 5.2.3 可见性控制

模块顶层的变量、函数、结构体等默认公开；使用 `私有` 关键字则限制为模块内可见。可见性检查在语义分析阶段完成。

##### 5.2.4 循环依赖检测

编译器通过深度优先搜索检测模块间的循环依赖。如果存在 A 导入 B、B 导入 A 的情况，报告错误并拒绝继续编译。

##### 5.2.5 编译单元与链接策略

每个 `.智` 文件编译为一个独立的 LIR 模块。在编译模式下，每个模块被独立翻译为 Cranelift IR，生成独立的目标文件。修改单个模块只需重新编译该模块及其直接依赖者。

**路径补全规则**：编译器读取 `项目依赖.配置` 中的 `路径` 字段后，按以下规则补全为完整物理路径：

| 路径开头    | 库类型     | 补全方式                                                  |
| :---------- | :--------- | :-------------------------------------------------------- |
| `.智语言/`  | 全局级库   | 读取 `全局.配置` 中 `全局目录` 的父目录，再拼接此相对路径 |
| `外部语言/` | 外部语言库 | 在路径前直接拼接项目目录                                  |
| 其他        | 项目级库   | 在路径前直接拼接项目目录                                  |

**展开导入的编译语义**：展开导入仅影响前端符号解析阶段，编译后符号仍然属于原模块，链接器通过正常的符号解析处理跨模块引用。展开导入不改变模块间的依赖关系。

##### 5.3.1 库管理器职责

│   │   └── 源码/

#### 5.5 最佳实践

##### 5.5.1 项目组织

按功能领域拆分模块，限制单个模块文件不超过 500 行。优先公开函数而非变量。依赖方向单向：入口层 → 服务层 → 模型层 → 工具层。

##### 5.5.2 错误处理模式

异常控制适用于处理可能失败且失败原因超出调用者控制范围的操作。一个 `捕获:` 块应包含逻辑上不可分割的最小操作单元。

##### 5.5.3 并发编程模式

- **生产者-消费者模式**：通道关闭是生产者通知消费者"没有更多数据"的信号。
- **扇出-扇入模式**：并行处理，汇聚结果。
- **多路监听模式**：使用 `并发.多路监听` 同时等待多个通道或事件。

##### 5.5.4 性能优化建议

- 开发期使用解释器快速迭代，发布期使用编译器获得最佳性能。
- 减少循环内堆分配——将对象创建移到循环外复用。
- 利用 COW 减少拷贝——在只读场景下赋值和传参仅增加引用计数。
- 利用编译器逃逸分析——独占对象写入时跳过 COW 检查，不逃逸对象栈上分配。
- 避免过细粒度的任务——使用 `并发.批量等待` 而非逐个等待。

### 第六部分 开源协作

开源协作是智语言项目从工具链走向生态的关键一步。本章定义了项目的开源许可证、贡献指南、社区治理模型、沟通渠道、项目路线图和贡献者致谢机制。


#### 6.1 开源许可证

智语言项目采用 **MIT 许可证**。MIT 是一种宽松的许可证，允许任何人在遵守许可证条款的前提下自由地使用、复制、修改、合并、出版发行、再授权及销售本软件的副本，只需保留版权声明和许可声明即可。

选择 MIT 许可证基于以下考虑：

- **最大化采用率**：MIT 限制最少，不要求修改后的代码必须开源，不限制商业使用。
- **与 Rust 生态一致**：Rust 语言和绝大多数 Rust 生态中的库都使用 MIT 或 Apache 2.0 许可证。
- **简洁易懂**：MIT 许可证全文仅有一页，符合智语言"简洁为纲"的设计哲学。


#### 6.2 贡献指南

**行为准则**：智语言项目遵循贡献者公约（Contributor Covenant）。核心原则包括使用友好和包容的语言、尊重不同的观点和经验、优雅地接受建设性批评、关注对社区最有利的事情。

**如何提交 Issue**：

- **错误报告**应包含：问题摘要、复现步骤、期望行为和实际行为、环境信息。
- **功能请求**应包含：使用场景、建议方案、替代方案。

**提交代码流程**：遵循"Fork → Branch → PR → Review"的标准 Git工作流。分支命名遵循 `类型/简短描述` 格式。提交信息说明"做了什么"和"为什么"。

**代码风格与测试要求**：Rust 代码使用 `rustfmt` 格式化，通过 `cargo clippy` 检查。遵循全中文命名约定。新功能必须包含测试用例。


#### 6.3 社区治理模型

**维护者团队**：维护者是项目的核心决策群体，职责包括审查和合并 PR、管理 Issue、制定项目路线图、发布新版本、执行行为准则。维护者团队成员之间地位平等，决策通过协商达成共识。

**决策机制（RFC 流程）**：重大变更（新语言特性、重大 API 修改、架构变更）通过 RFC 流程决策：提出 → 讨论（至少两周）→ 修订 → 决策（维护者团队评估）→ 实施。

**贡献者晋升路径**：贡献者 → 活跃贡献者 → 审查者 → 维护者。晋升基于持续的贡献记录、高质量的代码贡献和社区参与。


#### 6.4 沟通渠道

项目根目录的 `CONTRIBUTORS.md` 文件列出所有代码贡献者的名单。每次发布新版本时，在 Release Notes 中单独致谢新贡献者。所有贡献形式都被认可——包括报告错误、编写文档、帮助用户、设计视觉标识和组织社区活动。

代码段包含所有函数的字节码指令序列。指令格式为**显式寄存器操作数编码**：1 字节操作码 + 变长操作数。操作数的编码方式为 1 字节类型标记 + 操作数数据。

| 标记值 | 类型           | 数据长度 |

| `0x03` | 常量池索引     |    2     |
| `0x04` | 虚拟寄存器索引 |    2     |
| `0x05` | 全局变量索引   |    2     |
| `0x06` | 基本块索引     |    2     |
| `0x07` | 函数索引       |    2     |
| `0x08` | 字段索引       |    2     |
| `0x09` | 类型表索引     |    2     |

##### C.7 操作码分配

| 类别     |  编码范围   | 说明                                                         |
| :------- | :---------: | :----------------------------------------------------------- |

##### E.8 主要差异总结

1. **全中文关键字**（43个，含4个可省略）：智语言是唯一全部使用中文关键字的语言。
2. **类型标注前置**：`整数 年龄`，与 Go 一致。
3. **代码块闭合**：使用 `结束` 关键字。
4. **逻辑运算符仅中文**：`且`、`或`、`非`，不支持符号写法。
5. **无继承机制**：只支持结构体组合和接口适配。
6. **模块导入不加引号**：`导入 数学`。
7. **异常处理四段式**：`捕获: ... 异常: ... 始终: ... 结束`。
8. **任意类型统一泛型与联合**：智语言独有的原创设计。
9. **幂运算符 `^`**：与 Lua、R 一致。
10. **整除运算符 `%%`**：释放 `/` 给小数除法。
11. **参数传递显式选择**：默认传值，`传引用` 关键字声明传引用。
12. **索引起始从 1 开始**：数组、文本、遍历等所有位置索引均从 1 开始，未找到返回 0。
13. **转义序列中文化**：`\换行` 而非 `\n`。
14. **全中文工具链**：命令行工具、参数、帮助信息全部使用中文。
