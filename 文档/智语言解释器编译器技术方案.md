## 1.1 三层统一模型（理解本项目的总钥匙）

| 层 | 内容 | 唯一性 | 位置 |
| :--- | :--- | :--- | :--- |
| **L1 语义真相源** | 堆与容器语义、算术与比较、异常构造、标准库、并发、FFI 编组、类型系统 | 唯一 | `base`（运行时）+ 前端类型与作用域层 |
| **L2 契约层** | 运行时值 32 字节布局、opcode → base 委托单表、异常派发决策、字节码段格式 | 唯一 | 前端指令集 + `base` 布局定义 |
| **L3 执行引擎** | 字节码 VM 与 Cranelift 代码生成 | **必然两份** | `interpreter` / `compiler` |

**为什么 L3 必须双实现**：业界同构——CPython + JIT、Lua + LuaJIT、JVM 解释器 + C2、C# IL + JIT。差别不在「要不要两份」，而在**语义与契约是否单源**。

因此本项目的「彻底统一」可达上限是：**L1 + L2 单源，L3 的差异由契约与差分测试锁死**。执行引擎只做机械翻译，不允许包含语义决策。

推论（写代码时随时用来自检）：

- 任何「这个类型怎么算」的问题，答案在 `base`，不在任一引擎。
- 任何「这个操作码对应什么」的答案，在前端指令集的单表里，两个引擎都查它。
- 引擎里出现「如果是整数就……否则如果是小数就……」这类分支，基本都是语义外泄的信号。

> 真相源：`基础功能/src/运行时/值类型.rs`、`基础功能/src/运行时/堆操作.rs`、`前端/src/底层表示/指令集.rs`、`前端/src/语义/类型推导.rs`

## 1.2 工作区 crate 拓扑

| crate | lib 名 | 职责 | 允许依赖 |
| :--- | :--- | :--- | :--- |
| `frontend` | `frontend` | 词法 → 语法 → 语义 → 降级 | `base` |
| `basic_functions` | `base` | 运行时唯一真相（堆、系统函数、FFI、并发、网络） | 仅标准库 |
| `interpreter` | `interpreter` | 字节码生成 + VM | `frontend`、`base` |
| `compiler` | `compiler` | Cranelift 代码生成 + 链接 | `frontend`、`base` |
| `pm` | `pm` | 配置、目录、依赖解析、命名规范、网址规范化 | 无（最底层） |
| `libmgr` | `libmgr` | 库安装 / 解包 / 发布 | `pm` |
| `launcher` | `launcher` | 命令面 + 引导程序 + 发布 | `pm`、`libmgr`、`frontend`、`base` |
| `editor_service` | `editor_service` | LSP 语言服务（独立 EXE） | `frontend`、`pm` |
| `mock_server` | `mock_server` | 网络测试用模拟服务 | `base` |

依赖方向是**单向的**：`base` 不依赖 `frontend`；两个引擎都只依赖 `frontend` 产出的 LIR，不互相依赖。

- 引擎不互相依赖 ⇒ 允许「只修编译模式」或「只修解释模式」的增量开发，不会互相阻塞。
- `base` 不依赖 `frontend` ⇒ 运行时语义不需要知道前端类型系统的存在，编译期信息一律在边界处擦除。
- `pm` 不依赖任何语言实现 ⇒ 项目/库管理可以独立演进。

> 真相源：根 `Cargo.toml`（成员列表）、各 crate 的 `Cargo.toml`（依赖段）、`源码/前端/Cargo.toml`、`源码/基础功能/Cargo.toml`

## 1.3 双模式流水线

```
源码 ──▶ 词法 ──▶ 语法 ──▶ 语义 ──▶ 降级(LIR) ──┬─▶ 字节码 ──▶ VM        （解释模式）
                                                └─▶ Cranelift ──▶ 链接 ──▶ 产物（编译模式）
                                                     ▲
                                          唯一的语义分叉点
```

关键事实：

- **前端完全共享**：两种模式跑的是同一份词法、语法、语义、降级代码。因此「两模式行为不同」只可能源于 L3（引擎）或 base 侧的实现缺陷，不可能源于前端分歧。
- **分叉点在 LIR 之后**：降级层输出的是三地址码 + 基本块，既能被字节码生成器消费，也能被 Cranelift 消费。
- **入口约束**（规范 §2.8）：模块顶层只允许声明，唯一执行入口是 `启动程序()`，两种模式一致。降级层把顶层初始化序列前插到启动程序的第一块（**不是**在文件顶层执行）；复杂表达式复用完整表达式降级，仅「顶层初始化含分支或短路」这一窄口尚未支持（见 2.5.6）。
- **语义错误在两模式都必须暴露**：`测试` 命令在解释与编译两种模式下都先执行语义分析，否则负向用例在编译模式可能因「根本没走到编译」而被误判为通过（见 5.6.5）。

> 真相源：`前端/src/流水线.rs`、`前端/src/降级/`（`公共降级.rs` / `函数转换.rs` / `语句转换.rs`）、`后端/解释器/src/字节码生成.rs`、`后端/编译器/src/代码生成/`

## 1.4 构建指纹与缓存失效

缓存失效由**源树内容指纹**驱动，不靠人工 bump 版本号。

| 指纹 | 覆盖范围 | 生成方式 |
| :--- | :--- | :--- |
| 前端指纹 | `源码/前端/src` | `源码/版本管理器/build.rs` 遍历文件树，哈希后经 `cargo:rustc-env` 注入 |
| 基础指纹 | `源码/基础功能/src` | 同上 |
| 编译器指纹 | `源码/后端/编译器/src` | 同上 |
| 解释器指纹 | `源码/后端/解释器/src` | 同上 |

配套约定：

- `编译器逻辑版本` 常量**只用于人类可读展示**，不参与任何失效判定。历史教训：靠人改版本号必然漏改，漏改的后果是「改了代码却命中旧缓存」。
- 缓存键 = 源集合哈希 + 激活版本 + 各层指纹（详见 5.5.1）。任一分量变化即失效。
- `base.lib` 新鲜度同样用指纹判定：链接器从产物字节读出 `ZHI-BASE-FP:<hex>` 与当前基础指纹比对，取代 mtime 启发式（详见 5.5.2）。

> 真相源：`源码/版本管理器/build.rs`、`源码/版本管理器/src/构建签名.rs`、`源码/版本管理器/src/命令/运行命令.rs`、`源码/版本管理器/src/命令/编译命令.rs`

## 1.5 跨平台抽象层

平台差异统一收敛到 `base` 的 `平台` 模块，业务层禁止出现平台判断。

| 能力 | 接口 |
| :--- | :--- |
| 标识与命名 | `标识()` / `名称()` / `架构()` / `全标识()` / `可执行文件名()` |
| 库文件命名 | `库前缀()` / `库后缀()` / `动态库前缀()` / `动态库后缀()` |
| 进程与外壳 | `外壳()` / `子进程路径()` / `使可执行()` |
| 动态库加载 | `加载器路径()` |
| 路径兼容 | `兼容路径()` / `延迟删除目录命令()` |

铁律：

1. **业务代码禁止 `cfg!(target_os)`**，一律引用 `base::平台`。
2. 平台分支只允许出现在 `平台/windows.rs`、`平台/linux.rs`、`平台/macos.rs` 三个文件里。
3. 目录相关操作（全局目录、安装路径、可执行文件名）必须走平台抽象，避免 Windows 中心假设。

> **已知偏离**：`链接器.rs` 仍直接使用 `cfg!(target_os)` 做三平台分支（链接器程序选择 + 产物后缀），未收敛到平台抽象。属工具链层，收敛时需同步验证三平台（登记为附录 E 的 E-F4）。

> 真相源：`基础功能/src/公共服务/平台/{mod,windows,linux,macos}.rs`、`文档/跨平台技术方案.md`

## 1.6 实现命名约定

- **全中文标识符**：crate / 模块 / 目录 / 函数 / 变量一律中文实词组合；禁止英文借词与拼音直译（例如不写 `native`、`builtin`）。
- **保留字分层**：关键字（硬保留）/ 上下文关键字（按位置生效）/ 保留名（结构体成员专用）三层分开管理，避免「为了将来启用某个关键字而先占用它」。
- **一词一义**：同一概念在 `前端`、`base`、工具链三处必须用同一个中文词，不得出现同义词漂移（例如「深拷贝」与「复制数据」混用）。
- **英文只出现在**：标准库对外 API 名称、C 标识符、协议字段、第三方库原名。

> 真相源：`前端/src/词法分析.rs::关键字映射表`、`前端/src/词法分析.rs::是词法保留词条`、`pm::命名规范`

# 第二部分 前端

> 本部分回答「源码怎样变成可执行指令」。前端只做**语义正确的事**，不做**引擎相关的事**：它不认识解释器，也不认识 Cranelift。

## 2.0 分层与职责

| 层 | 输入 → 输出 | 关键约束 |
| :--- | :--- | :--- |
| 词法 | 源文本 → 词条流 | 全角归一化；关键字三层分类 |
| 语法 | 词条流 → 语法树 | 单遍递归下降 + Pratt；歧义在语法层消解 |
| 语义 | 语法树 → HIR | 作用域、类型、约束、模块成员可见性 |
| 降级 | HIR → LIR | 三地址码 + 基本块；**唯一**的语义分叉前阶段 |

四条贯穿全篇的原则：

1. **信息只增不减**：每层只允许增加信息（位置、类型、槽位），不允许在后续层「再猜一次」。类型在语义层定案，降级层只做映射。
2. **错误早报**：能在词法/语法/语义发现的错误，不留到运行期。
3. **单遍优先**：语法与语义都尽量单遍完成，避免多趟带来的状态漂移。
4. **反糖只在语义层**：降级层没有作用域信息，不能做糖的拆分（见 2.5.4）。

> 真相源：`前端/src/流水线.rs`、`前端/src/词法分析.rs`、`前端/src/语法分析/`、`前端/src/语义/`、`前端/src/降级/`

## 2.1 词法分析

### 2.1.1 关键字的三层分类

分类的目的：**让「将来可能启用的词」不必立刻占用名字空间**。

| 类别 | 例子 | 处理方式 |
| :--- | :--- | :--- |
| 硬关键字 | `如果` `循环` `函数` `返回` `结构体` `接口` `枚举` `导入` `抛出` | 任何位置都不能作标识符 |
| 上下文关键字 | `自身` `本模块` `初始化` | 只在特定位置被识别为关键字，其它位置是普通标识符 |
| 保留名 | 结构体成员名 `初始化` | 声明结构体成员时单独校验 |

补充规则：

- **保留字**只有 `公开`、`变量`、`传值` 三个：它们只**禁止命名**，语法层不把它们当声明或标识符，命中即给定向诊断（`传值` 在形参位置被消费，仅用于报「参数默认就是传值，不需要写 `传值` 修饰符」）。
- `初始化` 保留给结构体的初始化方法；用户不得自定义同名方法。

> 真相源：`前端/src/词法分析.rs::关键字映射表`、`前端/src/词法分析.rs::是词法保留词条`

### 2.1.2 字符集与全角归一化

- 源码按 **UTF-8** 读取；标识符允许中文。
- `全角映射()` 把 23 个全角字符折成半角（含中文引号 `“ ”`、全角竖线、全角脱字符、全角货币符号），使 `输出（1）` 与 `输出(1)` 等价，避免中英文标点混用造成的隐性差异。
- 注释：`#` 行注释、`/* */` 块注释。

> 真相源：`前端/src/词法分析.rs::全角映射`

### 2.1.3 一个典型案例：最小负整数字面量

`-9223372036854775808` 是 `i64` 的最小值，但**正值本身超出 `i64` 范围**，常规写法会先在正值处报错。

处理方式：

1. 词法层遇到超出 `i64` 正值范围的整数时，产出 `待定负整数(u64)`（携带原始幅值）。
2. 语法层仅在**一元负号紧邻**该词条时折叠为 `字面值::整数(i64::MIN)`。
3. 其它位置的 `待定负整数` 一律报错「整数常量超出 64 位有符号整数范围」，**不静默截断**。

> 真相源：`前端/src/词法分析.rs`（`待定负整数` 产出）、`前端/src/语法分析/表达式语法分析.rs`（一元负号折叠分支）

### 2.1.4 字符串、转义序列与注释

- 字符串用中文引号或 ASCII 双引号均可，序列化为 UTF-8。
- 转义序列是**中文命名**的（例如 `"\反斜杠d+"` 表示正则里的 `\d+`），不是 `\n` 这类英文缩写；理由是「转义什么」属于语言语义，应与语言同语种。
- 词法层只负责把转义还原为字节，**不解释正则语义**；正则属工具库。

> 真相源：`前端/src/词法分析.rs`、`文档/智语言编程规范文档.md` §2.2

## 2.2 语法分析

### 2.2.1 顶层结构

| 语法位置 | 允许内容 |
| :--- | :--- |
| 模块顶层 | 结构体、接口、枚举、函数、变量声明、导入、常量声明、外部块、导出块 |
| 函数体 | 声明语句、赋值、表达式语句、控制流、异常处理 |
| 模块顶层**不允许** | 任何可执行语句（唯一入口是 `启动程序()`） |

> 真相源：`前端/src/语法分析/语法分析器.rs`、`前端/src/语法分析/语句语法分析.rs::解析语句`

### 2.2.2 不依赖缩进

智语言**不使用缩进决定语义**：

- 语句边界由换行、显式 `结束`、以及右花括号 `}` 共同确定。
- 结构体与方法体用 `结束` 明确闭合；**不依赖缩进层级**。
- 这是刻意的选择：缩进对「给人读」友好，但对「跨编辑器、跨格式化器」脆弱；智语言选择用显式关键字换取确定性与可解析性。

代价：块结构在视觉上不如 Python 直观，需要靠关键字与空行组织可读性。

> 真相源：`前端/src/语法分析/语句语法分析.rs`（不读取缩进）、`文档/智语言编程规范文档.md` §2.2

### 2.2.3 上下文敏感位置

少数词条的含义取决于位置，语法层需显式处理：

| 位置 | 现象 | 处理 |
| :--- | :--- | :--- |
| 模块顶层 | `自身` 无意义 | 报错或按标识符处理 |
| 方法体内 | `字段名` 可能指裸字段 | 语义层优先按「结构体作用域」解析为 `自身.字段`（见 2.3.2） |
| 形参列表 | `传引用` / `传值` | `传引用` 合法；`传值` 触发定向诊断 |
| `本模块` 之后 | 只能是成员访问 | 前缀剥离在语义层完成 |

> 真相源：`前端/src/语法分析/语句语法分析.rs`、`前端/src/语义/表达式分析.rs`

### 2.2.4 语法错误的质量要求

诊断必须满足三条：给**位置**、给**原因**、给**可操作建议**（不是「请检查语法」）。同一根因只报一次，不做级联误报；错误恢复以「跳到下一个 `结束` 或顶层定义起始」为界。

> 真相源：`前端/src/诊断收集器.rs`（`帮助信息`、`是否是指` 字段）

### 2.2.5 语句的分派顺序（歧义在语法层就消掉）

`解析语句` 是一个 **match 定归属**的扁平分派，不做回溯搜索——分派顺序本身就是设计。

| 起始词条 | 去向 | 关键约束 |
| :--- | :--- | :--- |
| `公开` / `变量` / `传值` | 定向报错后跳过 | 保留字，不作声明或标识符 |
| `函数` | 先试「函数类型变量声明」 | 见消歧 ③ |
| `如果` / `循环` / `捕获` / `常量` / `私有` | 对应语句 | `私有` 仅用于模块顶层与结构体成员 |
| `跳出` / `继续` | 循环控制 | 必须在循环体内，否则语法错误 |
| `返回` | 有值 / 无值返回 | 见消歧 ④ |
| `抛出` | 抛出语句 | 后**不许**跟 `(`：`抛出(…)` 报错；正确写法 `抛出 异常错误(…)`；裸 `抛出` = 重抛 |
| 类型关键字（`整数`/`小数`/`文本`/`逻辑`）/ `空值` / `任意` | 变量声明 | 类型位置才消费这些词条 |
| `自身` / `本模块` | 先解析完整表达式，再看是否跟赋值符 | 跟 ⇒ 赋值；不跟 ⇒ 表达式语句。写回目标就是表达式本身 |
| `标识符` | `是类型标注开始()` 为真 ⇒ 变量声明；否则同上 | 见消歧 ① |
| 其它 | 表达式语句 | 兜底 |

五处消歧必须留在语法层（降级层没有源码位置，「静默忽略」会被当成语法支持）：

1. **声明 vs 表达式**：`标识符 标识符 …` 可能是「类型名 变量名」，判定只由 `是类型标注开始()` 一处回答，禁止别处复制第二份判据。
2. **赋值只在语句层成立**：`词条转二元运算符()` 明确**不为任何赋值/复合赋值返回运算符**。否则 `自身.字段 += 1` 会被贪心解析成二元加法，写回目标整体丢失。`目标 op= 值` 由语句层拼成「表达式 + 赋值运算符 + 表达式」。
3. **`函数` 的三义**：匿名函数字面量 / 误当定义关键字 / 函数类型变量声明。判据是扫到**圆括号深度 0** 的 `:` 与 `=` 谁先出现：先 `:` ⇒ 前两种，先 `=` ⇒ 声明。
4. **`返回` 的无值形式**：跳过换行后若为 `结束` / `否则` / `否则如果` / `异常` / `始终` ⇒ 无值返回。`始终` 必须在列表里，否则 `捕获 … 始终 …` 中的裸 `返回` 会被当成有值返回并吞掉下一行。
5. **循环三形态**：`循环 条件:`、`循环 i = 起, 条件, 步进:`、`循环 x[, y] 遍历 容器:`。`循环 当 索引 <= 3:` 曾是事故源——`当` 被读成类型名、整句退化为类型标注表达式、条件恒假 ⇒ **循环静默零次执行**；现在语法层直接给纠正诊断。

**分号规则**：分号只在函数体内合法（一行多语句）；控制流关键字后不许分号；循环三段式只认逗号。顶层用换行分隔语句。

> 真相源：`前端/src/语法分析/语句语法分析.rs`、`前端/src/语法分析/表达式语法分析.rs::词条转二元运算符`

### 2.2.6 表达式文法：Pratt 优先级爬升

结构只有「一个入口 + 一个循环」：

```
解析表达式()            = 解析表达式最小优先级(1)
解析表达式最小优先级(n) = 解析前缀(); loop {
                             后缀 `.成员` / `[索引]` / `(实参)`  ⇒ 消耗后继续（绑定最紧）
                             二元: p = 优先级(当前词条);  若 p < n ⇒ 停
                                   左 = 二元(左, op, 解析表达式最小优先级(p + 1))
                          }
```

| 性质 | 口径 | 理由 |
| :--- | :--- | :--- |
| 结合性 | 右操作数取 `p + 1` ⇒ **所有二元运算符左结合**（含 `^`） | 规范 §2.6.6 明写「同级从左到右」。实测 `2 ^ 3 ^ 2` = **64**（不是 512）；幂连乘请显式加括号 |
| 后缀最紧 | `.` / `[` / `(` 在循环内直接消耗 | 保证 `a.b(c)[d]` 链式成立，也省去一张后缀优先级表 |
| 一元 | `非` / `~` / `-` 的操作数用 `最小优先级(100)` | 规范把一元排在只低于括号/后缀的第 2 级。历史缺陷：`~` 曾用较低优先级，导致 `~5 == -6` 被解析成 `~(5 == -6)`，对逻辑值位非即抛异常；`非` 同批统一（`非 甲 == 乙` 现在等价 `(非 甲) == 乙`，与 C/Go/Java/C# 一致） |
| 刻度是内部值 | `2/4/5/6/7/8/9/11/12/13/14` | 只表示**次序**，空出的编号便于将来插层；**不要求**等于规范表格的 1–13 编号 |

**由紧到松的实现次序**：后缀 → 一元（100）→ `^` → 乘除整除取余 → 加减 → 移位 → 位与 → 异或 → 位或与属于 → 比较 → 且 → 或 → 赋值（仅语句层）。

> ⚠ **已登记偏差**：`属于` / `不属于` 的优先级与规范 §2.6.6 / 附录 B 不一致（规范与 `且` 同级，实现与位或同级且比比较紧），导致 `甲 属于 列表 == 真` 的分组与规范写法不同。处理方向待裁定，见附录 E。

两个陷阱级实现点：

- **类型标注表达式**：`标识符 标识符` 可能被读成「类型名 变量名」。规则是「类型名候选 + 后随标识符」，但只要**后随任意二元运算符即判为非类型标注**；且「是不是运算符」的判断必须复用优先级表——曾手写第二张表，导致数组字面量的类型标注误判，进而触发编译期死循环与巨量内存占用。
- **命名参数**：实参位置先尝试 `标识符 =` 前缀（备份游标，不成即回退），因此 `f(甲 = 1)` 是命名参数、`f(甲 == 1)` 是表达式，无需向前看两个词条。

**深度保护**：表达式递归计数超限直接中止并报语法错误；诊断环境变量可打印计数与深度，判读方法是「计数暴涨而深度不涨 = 循环未推进」，两者同涨 = 深递归。

> 真相源：`前端/src/语法分析/表达式语法分析.rs::优先级`、`前端/src/语法分析/表达式语法分析.rs::解析表达式最小优先级`

### 2.2.7 类型文法

`解析类型表达式` 是所有类型位置的唯一入口（变量、形参、结构体字段、容器元素、任意约束范围）。

| 形态 | 示例 | 说明 |
| :--- | :--- | :--- |
| 基本类型 | `整数` `小数` `文本` `逻辑` `空值` | 前三者是词法层专属词条，不是普通标识符 |
| 容器 | `数组<…>` / `映射<K, V>` | 省略 `<>` 时元素或键值落 `空值`（未约束） |
| 任意四形态 | `任意` / `任意<甲>` / `任意<甲\|乙>` / `任意<甲: 约束>` | 语义见 2.3.3 |
| 泛型 | `任务<整数>` / `通道<文本>` / `字典<文本, 整数>` | 名称 + 类型参数列表 |
| 限定类型 | `几何.点` | 跨模块限定 |
| 函数类型 | `函数(整数, 整数) 整数` | 一等函数，可出现在任意类型位置 |
| 函数指针 | `函数指针(…) 返回类型` | FFI 回调形参（3.9） |

形参列表统一处理 `[传引用] 类型? 名称 [= 默认值]`：`传引用` 显式写出；`传值` 是默认且禁止写出。结构体成员声明走 `解析结构体成员列表`，规则见规范 §2.3.5 与常量条款。

> 边界：类型的**语义**（约束、空值收窄、接口适配）在 2.3；对外**全表**在规范 §2.4/§2.5；本节只固定「入口在哪、怎么消歧」。

> 真相源：`前端/src/语法分析/类型语法分析.rs`

## 2.3 语义分析

### 2.3.1 职责边界

语义层负责：作用域与符号解析、类型推导与检查、模块成员可见性、泛型单态化、反糖、运算符重载分派。**不负责**：生成指令、决定槽位、决定异常派发目标。

判据：凡是「换个执行引擎答案会不会变」的问题，都属于语义层，必须在这一层定案。

### 2.3.2 符号表与作用域

- 作用域为**词法作用域**：模块 → 函数 → 代码块 → 循环体。
- 遮蔽靠**内层同名绑定**实现；模块级变量在函数内**必须**写 `本模块.名称` 访问，裸名访问会被明确报错（否则「函数内同名局部」与「模块级变量」无法区分）。
- 结构体方法内，裸字段名优先解析为 `自身.字段`；构造参数在方法体内**不**注册为变量，避免与方法体同名局部混淆。
- 模块级变量与常量重名直接报错（补 `return Err`，不静默忽略）；判定时带「同文件」护栏，避免把导入进来的成员误判为本地重名。

> 真相源：`前端/src/语义/符号表.rs`、`前端/src/语义/语句分析.rs`、`前端/src/语义/语义分析器.rs`

### 2.3.3 类型系统

四种基本形态与两种「动态」形态并存：

| 形态 | 说明 |
| :--- | :--- |
| 基本类型 | `整数` `小数` `文本` `逻辑` `空值` |
| 容器 | `数组<T>` `映射<K, V>`，元素类型受约束 |
| 命名类型 | 结构体、接口、枚举 |
| 泛型 | 带类型参数的容器与任务类 |
| 任意（裸） | 无约束的动态值 |
| 任意（有名/联合） | `任意<甲>`、`任意<甲\|乙>`、`任意<甲: 约束>` |

要点：

- **裸 `任意` 与联合 `任意` 是两件事**：前者无约束，后者有约束范围；实现上二者的约束检查路径不同（见 2.3.5）。
- **未推断类型不等于 `空值`**：类型推断失败必须报错，禁止把「没推断出来」降级为「空值」，否则错误会被静默传播。
- **类型收窄只支持空值收窄**：见 2.3.10。

> 真相源：`前端/src/语义/类型信息.rs`、`前端/src/语义/类型推导.rs`、`前端/src/语义/类型推断.rs`

### 2.3.4 泛型与单态化

- 泛型函数在**调用点**单态化：按实参类型实例化出具体函数，再参与后续降级。
- 含任意类型形参的函数走**单态化早返回**路径：签名中的形参类型会被清空，因此后续的约束检查不能依赖签名。
- 泛型容器的元素类型在推导失败时不得静默变成 `空值`。

> 真相源：`前端/src/语义/泛型解析.rs`、`前端/src/语义/表达式分析.rs`

### 2.3.5 类型检查与约束

三条检查路径，**必须都接上**，否则会出现「换个调用方式就绕过检查」：

| 路径 | 触发方式 | 检查点 |
| :--- | :--- | :--- |
| 标识符调用 | `函数(…)` | 调用处做任意类型约束检查 |
| 单态化 | 含任意类型形参的函数 | 匿名约束校验在实例化时补 |
| 成员访问 | `模块.函数(…)`、`对象.方法(…)` | **历史上遗漏**，需在成员访问路径补齐约束检查 |

已知缺口：成员访问路径的任意类型约束检查不拦截（`数学.平方根("abc")` 会被放行），登记于附录 E。

> 真相源：`前端/src/语义/类型检查.rs::检查任意类型约束`、`前端/src/语义/表达式分析.rs`

### 2.3.6 编译期求值

常量表达式在语义层求值（编译期求值），用于：数组长度、枚举值、常量声明、结构体字段初值。

- 求值失败必须是**显式错误**，不得回退为「运行时再算」。
- 求值只允许纯表达式：不允许调用用户函数、不允许读取可变变量。

> 真相源：`前端/src/语义/编译期求值.rs`

### 2.3.7 「本模块」与模块级成员访问

| 规则 | 内容 |
| :--- | :--- |
| 访问方式 | 模块级变量 / 常量必须写 `本模块.名称`；裸名访问报错 |
| 写入 | `本模块.名称 = 值` 走与普通赋值一致的语义，但目标必须是本模块成员 |
| 多层路径 | `本模块.容器.方法()` 允许：根名（`容器`）被登记后放行 |
| 遮蔽 | 函数内同名局部**允许**遮蔽模块级变量（此时读模块级变量必须写 `本模块.`） |

实现要点：

- `本模块` 在**词法层**是独立词条，在**语法层**与 `自身` 同款处理（成员访问的基对象），因此 `本模块.X` 天然成为成员访问节点。
- 语义层做**前缀剥离**：把 `本模块.X` 归一为对模块顶层符号 `X` 的引用，从而与「裸名路径」共用同一 HIR 形态，降级层零改动。
- 裸名路径必须与模块级解析路径**解耦**：否则 `本模块.` 会被裸名路径拦下（裸名路径已排除模块级成员）。
- 判定「是不是模块级成员」必须比对**定义位置**，不能只看「名字在表里」——否则内层同名局部会被误拦。

> 真相源：`前端/src/语义/表达式分析.rs::剥离本模块前缀`、`前端/src/语义/表达式分析.rs::查找本模块成员`、`前端/src/语义/语义分析器.rs`

### 2.3.8 接口与自动适配

- 接口是**引用语义**：赋值、传参只复制标签（句柄 + 计数），不深拷贝。
- 调用接口方法走**接口分发**：按运行期实际类型找到结构体的方法实现。
- 实现类必须满足接口签名；缺方法、签名不符在语义期报错。
- 接口调用是**两引擎共同路径**：分派决策在 base/前端，后端只做间接调用。

> 真相源：`前端/src/语义/表达式分析.rs::生成接口分发调用`、`基础功能/src/运行时/堆操作.rs`

### 2.3.9 枚举与数据枚举

- 枚举在 HIR 中保留定义（成员名与成员索引按名稳定排序），因此运行期可以还原「标签 → 名称」。
- 枚举的运行期表示是**堆数组** `[标签, 数据…]`；数据枚举把成员数据平铺进同一数组。
- 枚举可作映射键的前提是运行期能识别「这个数组其实是枚举」——这也是 HIR 必须保留枚举定义的原因。

> 真相源：`前端/src/语义/高层表示节点.rs`、`基础功能/src/运行时/堆操作.rs`

### 2.3.10 可空类型与空值收窄

- 可空 = 联合类型中含 `空值`。
- 收窄机制**当前只支持空值收窄**：形如 `甲 != 空值` 之后，`甲` 被收窄为非空。联合类型的其它分支**没有**基于 `类型()` 的收窄。
- 匿名任意类型必须显式初始化（含含 `空值` 的联合也无豁免）；唯一例外是结构体字段——字段走另一条路径，缺失初值时补 `空值`。

> 真相源：`前端/src/语义/语句分析.rs`（空值收窄）、`前端/src/语义/类型信息.rs`

### 2.3.11 类型转换与类型判断

- 显式转换（`整数(…)`、`文本(…)` 等）是**受检操作**：转换不可行时报错，而不是产出 `空值`。
- 类型判断（`类型(x)`）返回类型名文本；**不得**用空值表达「判断失败」。
- 编译期类型收窄不跨分支：某些分支里判出的类型，在合并后的类型上不成立（例如「空值不能参与类型转换」）。

> 真相源：`前端/src/语义/类型检查.rs`、`前端/src/语义/表达式分析.rs`

### 2.3.12 参数传递：传值与传引用

| 方式 | 语义 | 代价 |
| :--- | :--- | :--- |
| 传值（默认） | 复合类型**深拷贝**后传入；标量直接复制 | 有拷贝开销，但调用方与被调方互不影响 |
| 传引用 | 传句柄；被调方**原地修改**调用方的对象 | 无拷贝，但调用方「改不动」（规范已明确该限制） |

要点：

- 深拷贝是**值语义的实现方式**，不是「优化」；它保证「赋值即隔离」在构造上成立。
- 传引用需要前端发射取地址 / 间接加载 / 间接存储三个操作码；三者缺一即表现为「编译模式改不动调用方」。
- 传引用形参是**借用**：不参与引用计数，不入释放清单。

> 真相源：`前端/src/语义/表达式分析.rs`、`前端/src/降级/语句转换.rs`、`基础功能/src/底层表示/指令集.rs`

### 2.3.13 运算符重载：分派在语义层，执行走方法调用

运算符重载**不是新执行机制**：语义层把 `甲 + 乙` 改写成 `甲.加法(乙)`，之后降级与两个引擎按普通方法调用处理，双模因此天然一致。

| 组 | 条目 | 参数数量（不含 `自身`） |
| :--- | :--- | :--- |
| 二元 | 加、减、乘、除、整除、取余、幂、等于、大于、小于、大于等于、小于等于、不等于、异或、位与、位或、左移、右移 | 1 |
| 一元 | 取负、位非 | 0 |
| 复合赋值 | 对应 12 个 `XX赋值` 方法 | 1 |

合计 **32 组**，与规范 §2.6.7 的可重载表逐项对应。方法名是唯一真相源，业务代码不得再硬编码 `"加法"` 之类字面量。

分派规则（按代码顺序）：

1. **只看左操作数的静态类型**；右操作数类型不参与决策。
2. **参数数量不符 ⇒ 视为普通公开方法，不参与分派**（规范 §2.6.7 规则 7）。
3. **一元特例**：结构体有 0 参 `取负` / `位非` ⇒ 方法调用；结构体**没有** ⇒ **编译错误**（不得回退成 `0 - 甲` 或 `甲 ~| -1`，否则对结构体算出空值）。非结构体保留数值回退。
4. **无匹配重载的结构体二元运算 ⇒ 编译错误**，诊断需可操作（指出「结构体【X】未定义 `+` 的 1 参重载方法」）。
5. **比较类重载必须返回 `逻辑`**。
6. **复合赋值必须显式定义**，不由二元推导：结构体的 `甲 += 乙` 直接调 `加法赋值`；基本类型的复合赋值仍走 `目标 = 目标 op 值`。
7. **数学 5 个内建结构体是例外**：它们的运算由 `base` 用 Rust 原生类型实现，前端只登记类型与方法表，经系统调用分派。

结果类型的双模铁律（三处必须一致）：比较恒 `逻辑`；`/` 恒 `小数`；整除恒 `整数`。

> 真相源：`前端/src/语义/运算符重载.rs`、`前端/src/语义/表达式分析.rs`、`文档/智语言编程规范文档.md` §2.6.7

## 2.4 HIR（高层表示）

定义在 `语义/高层表示节点.rs`。整体形态：`高层表示模块 { 函数列表, 全局变量列表, 结构体定义列表, 导入列表, 外部函数列表, 外部结构体列表, 导出函数列表, 库映射表, 枚举定义列表 }`。语句与表达式是**闭合枚举**。

四个设计决策必须理解，否则容易在降级层写出错误代码：

| 设计 | 内容 | 为什么 |
| :--- | :--- | :--- |
| `语句序列` 与 `代码块` 分离 | `语句序列` 是纯多语句容器，**不引入作用域**；`代码块` 是用户书写的内层块，**引入作用域** | 反糖（`循环 i = 1..N`）若用 `代码块` 打包，降级层会在块退出时清除循环变量，外部引用取到非法槽 |
| `变量声明.是否模块级` | 仅当公共降级注入顶层初始化语句时置真 | 降级层若只看**名字**是否在全局变量表，函数内同名隐式声明会被误写进全局槽 |
| `依赖自身` 标记 | 方法是否真的用到 `自身` | 决定 `实例.方法()` 是否传自身；静态判定优于运行时试错 |
| 枚举定义保留在 HIR | 成员名与索引按名稳定排序 | 否则运行期拿不到「标签 → 名称」，枚举渲染退化为 `[<标签>]`，也无法判定枚举能否作映射键 |

> 真相源：`前端/src/语义/高层表示节点.rs`

## 2.5 降级（HIR → LIR）

### 2.5.1 文件分工

| 文件 | 职责 |
| :--- | :--- |
| `公共降级.rs` | 模块级编排：函数索引登记、全局变量表、结构体布局、顶层初始化前插、系统函数名 → 索引映射 |
| `语句转换.rs` | 语句 → 基本块与指令；作用域与局部槽分配；异常控制流发射；反糖；内存插桩 |
| `函数转换.rs` | 函数级装配：形参槽、基本块序列、函数出口（释放 / 返回） |
| `类型转换.rs` | HIR 类型 → LIR 类型的**别名展开**与映射 |
| `类型擦除.rs` | 运行时不需要的类型信息丢弃 |
| `控制流结构化.rs` | **仅**提供降级上下文（基本块计数、局部变量分配、变量映射） |

> 命名注意：`控制流结构化.rs` 名字有误导性——它不是「把 CFG 结构化成 if/while」的分层器；HIR 本身已是结构化语句树。

> 真相源：`前端/src/降级/`

### 2.5.2 LIR 形态

- `底层表示模块` = 函数列表 + 全局变量 + 结构体定义；`函数` = **基本块列表**；`基本块` = 指令序列 + 终止指令（跳转 / 条件跳转 / 返回）。
- 指令是**寄存器式三地址码**：`结果槽 = 操作码 操作数…`。
- **局部槽 1-based**，`0` 预留给特殊用途；索引转换在后端完成，降级层保持 1-based。
- 变量映射 `变量名 → 局部索引` 由降级上下文维护；同名遮蔽靠**分配新槽**实现（不复用），因此块退出只需恢复映射，无需清零槽位。

> ⚠ **发射指令必须带结果槽**。字节码是寄存器式编码（dest + 操作数），若某指令填「无结果」，VM 解码会错位，表现为 `index out of bounds` panic。新增指令类型时必须显式分配临时槽。

> 真相源：`前端/src/降级/底层表示/`、`前端/src/降级/控制流结构化.rs`

### 2.5.3 类型擦除策略

`类型擦除.rs` 是一张**显式全表**（不做通配兜底）：

| HIR 类型 | LIR 类型 | 说明 |
| :--- | :--- | :--- |
| `整数` / `小数` | `整数64` / `小数64` | 基本型直映 |
| `文本` / `逻辑` / `空值` | 同名 | — |
| `数组` / `映射` / `结构体` / `枚举` / `接口` | `指针` | 运行期是堆句柄 |
| 任意 / 未推断 | `指针` | **动态值槽**，标签与载荷完整保留 |
| 函数类型 | `函数指针` | 闭包 / 回调 |
| 推断错误 | `空值` | 语义失败哨兵，不应进入代码生成 |

**禁止**把「未推断」归并到 `空值`。新增类型变体时必须同步改这张表——它没有 `_ =>` 兜底，编译器会强制你面对。

> 真相源：`前端/src/降级/类型擦除.rs`

### 2.5.4 反糖

语义层已把语法糖拆成基础节点，降级层只处理「基础节点的直接翻译」：

| 源码形态 | 语义层产物 |
| :--- | :--- |
| `循环 i = 1..N` | `语句序列[变量声明 i, 循环语句{条件 i<=N, 体, 步进 i=i+1}]` |
| `遍历 x 在 数组` / `遍历 k,v 在 映射` | `语句序列[索引/键/值声明…, 循环语句]` |
| 复合赋值 `a += b` | `赋值{a, 二元运算{a, +, b}}` |
| 字符串插值 | 拼接表达式 |
| `跳出` / `继续` | 直接映射为终止指令（目标块在语句转换期解析） |

反糖必须发生在**语义层**（有作用域信息），不能在降级层做——降级层只有局部槽，没有「这个名字属于哪个作用域」的信息。

> 真相源：`前端/src/语义/语句分析.rs`、`前端/src/降级/语句转换.rs`

### 2.5.5 异常控制流显式化（前端契约）

智语言的 `捕获 / 异常 / 始终` **不是**后端特性，而是前端发射的**显式控制流**。降级层把

```
捕获:      危险块
异常 e:    处理块
始终:      收尾块
结束
```

展成

```
危险块 → catch 入口 → 处理块 → 始终块 → 查全局变量(0) → 传播块 / 续延块
```

并遵守三条硬契约：

1. **每层 catch 入口必须复位待处理标志槽**（该槽承载「待处理 / 重抛」标志，见 3.6）。
2. **`始终:` 不允许后端另起 finally 状态机**：解释器侧的「当前 finally 块」只是动态派发机制，必须与本流对齐；编译器只做机械翻译。
3. **单一派发入口**：不允许「前端显式流 + 后端 finally 路由」两条路径叠加，否则续延代码会被到达两次（真实事故：跨调用帧异常后，`捕获` 之后的代码执行两遍）。

> 架构判据：**异常是控制流，控制流属于前端**。后端只实现「跳转 + 一个标志槽的读写」。

> 真相源：`前端/src/降级/语句转换.rs`（异常操作码语义契约）

### 2.5.6 顶层初始化前插

模块级 `变量 = 表达式` 在语义层被收进「启动程序第一块之前的初始化序列」：

- **正常运行**：该序列注入启动程序的第一块，随入口执行一次。
- **测试逐函数执行**：先单独调用这段初始化序列（按名定位），否则测试函数里的 `本模块.X` 读到空值，与编译模式产生假分歧（见 5.2.2）。

实现：简单形态（常量、空容器）直接在降级层发射；复杂表达式（含函数调用、容器字面量、嵌套）复用完整表达式降级路径，插入启动程序第一块。

**已知限制**：顶层初始化表达式含**分支 / 短路**（需要多基本块）时，降级给出警告并保持 `空值`。治本方向是把顶层初始化在语义层就「语句化前插」到入口函数体（与局部变量完全同源，原生支持短路与闭包），而不是在降级层打补丁。

> 真相源：`前端/src/降级/公共降级.rs`

### 2.5.7 流程控制的 LIR 形态

降级层把结构化语句展开成**基本块 + 条件跳转**，没有「高级控制流指令」：

| 语法 | LIR 形态 |
| :--- | :--- |
| `如果 条件:` / `否则如果` / `否则` | 条件块（条件跳转分真 / 假）→ 各分支块 → 统一汇合块 |
| `循环 条件:` | 条件块 → 循环体块 → 步进块 → 回跳条件块；循环结束后接「结束块」 |
| `遍历 x 在 数组` | 反糖为索引循环（2.5.4），索引 / 键 / 值是普通局部变量 |
| `跳出` | `无条件跳转(最内层循环的结束块)` |
| `继续` | `无条件跳转(最内层循环的步进块)` |

> 真相源：`前端/src/降级/语句转换.rs`

### 2.5.8 短路求值（多基本块）

`且` / `或` 是**有副作用的短路求值**，不能编译成单个布尔运算指令。LIR 形态是条件跳转 + 临时槽：

```
且:  求值甲 → 假则跳转(假值块) → 求值乙 → 合并
或:  求值甲 → 真则跳转(真值块) → 求值乙 → 合并
```

副作用：短路求值会引入额外基本块，因此「函数只有 1 个基本块」这类假设在含短路的函数上不成立（影响内存插桩的闸门，见 3.3.3）。

> 真相源：`前端/src/降级/语句转换.rs`

### 2.5.9 相等性语义

| 运算符 | 语义 |
| :--- | :--- |
| `==` / `!=` | **值相等**：复合类型逐层比较内容 |
| `===` / `!==` | **身份相等**：比较句柄（同一实例） |
| `实例相等` / `实例不等` | 与 `===` 同义的显式写法 |

空值比较有专门分支：`空值 == 空值` 为真、`空值 == 其它` 为假（不触发类型错误）。深相等与身份相等是两套实现，不得互相替代。

> 真相源：`基础功能/src/运行时/堆操作.rs`（堆_相等 / 堆_身份相等 等）、`前端/src/降级/语句转换.rs`

## 2.6 模块加载与导入

### 2.6.1 导入来源的分类

| 来源 | 写法 | 解析位置 |
| :--- | :--- | :--- |
| 核心库 | 免导入 | 内建 |
| 标准库 | 免声明，按模块名直接使用；也可聚合导入 | `标准库元数据::标准库种类` |
| 项目内模块 | `导入 相对/或/模块路径` | `模块加载器::解析文件路径` |
| 第三方库 | `导入 库名/模块路径` | `pm::依赖解析` 给出加载路径，`模块加载器` 装载 |

- **裸名只由「展开」修饰产生**：普通导入必须带命名空间前缀（`库名.函数`），除非显式写 `展开`。
- 导入**不能在函数体内**（规范 §2.7.3），语法层直接报错。

> 真相源：`前端/src/模块加载器.rs`、`前端/src/语法分析/语法分析器.rs::解析导入声明`、`pm/src/依赖解析.rs`

### 2.6.2 导入修饰

| 修饰 | 效果 |
| :--- | :--- |
| 无 | `库名.名称` |
| `别名 新名` | `新名.名称` |
| `展开` | 名称直接进入当前作用域（裸名） |

修饰语义由「命名空间前缀」统一表达：前缀 = 库名 / 别名名 / 无（展开）。

> 真相源：`前端/src/语法分析/语法分析器.rs`（导入声明的命名空间前缀字段）

### 2.6.3 加载器必须处理的四件事

1. **路径解析**：项目内候选根、作用域源码根、相对导入基准目录。
2. **递归装载**：带深度上限（thread-local 计数 + RAII 守卫）防止深递归。
3. **符号提取与合并**：`提取公开符号` 只导出公开成员；私有成员不跨模块可见。
4. **环与冲突检测**：同一模块重复导入、环形导入、「启动模块被导入」。

> 真相源：`前端/src/模块加载器.rs::加载依赖模块`、`模块加载器.rs::提取公开符号`、`模块加载器.rs::检测环形聚合`

### 2.6.4 项目外模块键

项目外的库以 `.智语言/` 前缀标识全局安装的库；项目内模块不带此前缀。路径补全规则：`库/<名><版本>/源码/`（项目级安装）与 `.智语言/<名><版本>/源码/`（全局级）。

> 真相源：`pm/src/目录.rs`、`pm/src/依赖解析.rs`

### 2.6.5 聚合导入

聚合导入把一个模块（或标准库聚合）下的多个成员一次性引入当前作用域。

- **同名歧义**：聚合引入的成员之间同名时必须报错，不做「后者覆盖前者」。
- **环形检测**：聚合 A 引入 B、B 引入 A 属错误，需显式报错。
- **标准库聚合**：标准库各模块可整体聚合导入，成员名仍保持规范中的模块归属。

> 真相源：`前端/src/模块加载器.rs::聚合对外名`、`模块加载器.rs::检测环形聚合`、`模块加载器.rs::合成标准库聚合符号`

## 2.7 诊断体系

`诊断收集器.rs` + `公共数据结构::诊断信息`，字段固定为：

```
级别 | 错误类型 | 描述 | 位置 | 也见于 | 是否是指 | 标记说明 | 帮助信息
```

| 字段 | 作用 |
| :--- | :--- |
| `也见于` | 同一符号多处定义时列出其它位置（替代「只报最后一处」） |
| `是否是指` | 拼写建议（编辑距离近邻），用于「未定义符号」 |
| `标记说明` | 源码片段下划线的注释 |
| `帮助信息` | 可操作的修复建议 |

- **全中文**（规范 §3.6 模板）；引用外部库原始报错时可保留原文。
- 输出去向见 2.0：结构化输出走 stdout，人读格式走 stderr。
- `诊断全局.rs` 提供跨模块的少量全局状态（如当前文件路径），避免层层透传。

### 2.7.1 失败分级：诊断 / Err / 异常 / panic 各管一段

最常见的架构性错误是「用错失败通道」。四类失败各有唯一归属：

| 失败性质 | 通道 | 理由 |
| :--- | :--- | :--- |
| **用户写错了**（语法、类型、参数、可见性） | 诊断信息（级别：错误 / 警告；错误类型共 10 类：语法、语义、类型、参数、运行时、资源、网络、并发、内部、代码建议） | 诊断可一次报多条、带位置与帮助信息；`Err` 只能带一条 |
| **后端缺实现 / 不变量被破坏** | 编译期 `Err`（拒编） | 静默产出空值会造成**隐蔽的双模分歧**，比拒编危险得多 |
| **运行时用户错误**（越界、除零、缺键、精度溢出、FFI 返回码非 0） | 语言层**可捕获异常** | 异常能被 `捕获 / 始终` 处理且双模一致；panic 会直接炸进程 |
| **前端自身不变量** | `panic!` | 这类是实现 bug，不是用户错误，必须大声失败 |

三条配套红线：

1. **警告不阻断**：`有错误()` 只统计错误级；「降级为 `空值` + 警告」是**有意的**保守策略，不是漏判。
2. **释放类原语必须幂等**：悬垂或重复释放静默忽略、不 panic，才能让「批量释放与顺序无关」（3.3.3 依赖这一点）。
3. **库函数禁止用「返回空值」表示失败**：`空值` 是合法数据；失败必须抛具名异常。FFI 边界同样按返回码判定并转成异常。

> 真相源：`前端/src/诊断收集器.rs`、`前端/src/流水线.rs`、`后端/编译器/src/代码生成/翻译执行器.rs`（P0 安全网）

# 第三部分 后端与运行时

> 本部分回答「指令怎么执行、对象怎么活下来」。两个引擎是**执行引擎**，不是**语义实现**：所有「这个值等于多少」的答案都在 `base`。

## 3.0 两个引擎的职责边界

| 引擎 | 输入 | 职责 | 明确不做 |
| :--- | :--- | :--- | :--- |
| 解释器 | 字节码 | 取操作数、调用 base、写结果槽、跳转 | 决定语义 |
| 编译器 | LIR | 生成机器码、链接成产物 | 决定语义 |

判据：引擎里出现「如果类型是 X 就……否则……」这类**类型分派**，基本都意味着语义外泄。正确做法是把该判断下沉到 base（用统一堆操作），或在语义层定案后由 LIR 携带足够信息。

## 3.1 base：唯一的运行时真相

### 3.1.1 依赖倒置的接线方式

`base` 不依赖前端，也不依赖任何引擎。调用方向永远是**前端 → base**：

| 环节 | 机制 |
| :--- | :--- |
| 堆操作 | 前端 opcode → `操作码到堆操作` 单表 → `base::堆操作` 常量 |
| 系统函数 | 前端登记名字 → 索引；运行期 `base::系统调用(索引, 参数)` |
| 数值运算 | 编译模式也**不内联**整数快路径，一律走 base 的 C ABI 运算入口 |

这条倒置带来两个直接好处：

- 两个引擎天然一致——它们调用的是同一批函数。
- 新增一个堆操作只需要改一处 base 与一张单表，不需要同时改两个引擎。

### 3.1.2 索引空间（跨 crate 契约）

| 空间 | 区间 | 真相源 |
| :--- | :--- | :--- |
| 系统函数 | `0 .. 用户函数索引基址`（当前最大**已用** 330） | `base/标准库索引.rs` |
| 用户函数 | `>= 用户函数索引基址`（当前 400） | `前端/底层表示/模块结构.rs` 常量 |
| 内建结构体类型 | `0..=15` | `base/运行时/值类型.rs` 命名常量 |
| 用户结构体类型 | `>= 用户结构体类型索引基址`（当前 16） | 同上 |

铁律：

1. **索引只有常量，没有魔数**。任何地方需要「用户函数从哪个号开始」，一律引用常量。
2. 契约测试必须校验「基址高于最大系统函数号」。
3. 历史事故：基址迁移（200 → 300 → 400）时有两处 `saturating_sub(300)` 漏改，导致两个用例在编译模式下失败。根因是**魔数复制**，因此规则是「只允许常量」。

> 真相源：`前端/src/底层表示/模块结构.rs`、`基础功能/src/标准库索引.rs`、`基础功能/src/运行时/值类型.rs`

## 3.2 值表示与全局堆

### 3.2.1 运行时值（32 字节扁平结构）

| 字段 | 宽度 | 含义 |
| :--- | :--- | :--- |
| 标签 | 8 字节 | 运行时类型标签（整数、小数、文本、句柄、空值、并发句柄、函数指针……） |
| 载荷 | 8 字节 | 标量值或堆句柄 |
| 句柄字段 | 8 字节 | 并发资源的句柄表示（与载荷字段并存的兼容位） |
| 保留 | 8 字节 | 对齐与扩展 |

要点：

- 标签与载荷**恒定 8 字节对齐**；编译模式的数据段必须 `set_align(8)`，否则读出的文本/数组会落在非对齐地址，表现为「编译模式读值异常、解释模式正常」这种极易误判为编译器 bug 的故障。
- 句柄 = `[代际 32 | 索引 32]`：槽位被回收复用时代际 +1 ⇒ 旧句柄解码即失效（ABA 防线）。

> 真相源：`基础功能/src/运行时/值类型.rs`

### 3.2.2 堆数据

堆里的对象按**闭合枚举**表示：文本、数组、映射、结构体、枚举、闭包环境、外部值等。

| 形态 | 关键字段 | 说明 |
| :--- | :--- | :--- |
| 文本 | 字节缓冲 / 静态指针 + 长度 | 静态文本零拷贝共享，修改时升级为拥有型 |
| 数组 | 元素槽数组 | 元素按值语义深拷贝存放 |
| 映射 | 键值对数组 | 键按规范化规则比较（见 3.2.3） |
| 结构体 | 类型索引 + 字段槽数组 | 字段访问走统一字段操作码 |
| 闭包环境 | 函数索引 / thunk 地址 + 捕获变量 | 编译模式用 thunk 地址替代函数索引 |

> 真相源：`基础功能/src/运行时/值类型.rs`

### 3.2.3 堆键：映射键的规范化

映射键必须「可比较」，因此键的规范化是**契约**：

- 文本键按内容比较（长度 + 字节）。
- 数值键按数值比较：**整数值的小数落回整数键**（否则 `1` 与 `1.0` 会成为两个键，违反「相等当且仅当同键」）；`-0.0` 归一为 `0.0`。
- 无效小数（NaN）**不能**作键，直接报错。
- 结构体 / 枚举作键有前置条件（须未自定义 `等于`），否则「相等」的语义不唯一。
- 键编码带**深度上限与路径环检测**：结构体可经 `空值` / `任意` 字段自引用，编码必须显式拒绝而不是无限递归。
- **兜底禁止**：无法规范化的键必须报错，不得静默变成空字符串键（否则不同键会碰撞，且碰撞后表现为「取不到刚放进去的值」）。

> 真相源：`基础功能/src/运行时/值类型.rs::值转键`

### 3.2.4 全局堆

| 项 | 事实 |
| :--- | :--- |
| 实例数 | **全局唯一单例**（进程内共享） |
| 容器 | `RwLock`；写操作取写锁，读操作取读锁 |
| 分配 | 首次分配走原子计数器，后续在锁内取槽位 |
| 空闲表 | 回收后的槽位进入空闲表复用 |
| 写入 | 写入前复制（写时复制）已退役，写入原地进行 |

**锁纪律**（违反即死锁）：

1. **写锁内不得再取读锁**（`RwLock` 不可重入升级）。
2. 级联释放在**同一次写锁内**以迭代工作队列完成，不递归取锁。
3. 业务层不得绕过堆接口直接改槽位。

> 真相源：`基础功能/src/运行时/值类型.rs`

### 3.2.5 COW 已退役（重要历史结论）

写时复制曾用于「值语义 + 共享引用」的折中，但**计数虚高**（存储侧 +1 而临时值未 −1）会导致误分离，表现为「改了副本却影响到原对象」。现结论：

- 写入**原地进行**，句柄恒不变。
- 隔离完全由「存储即深拷贝」承担。
- `堆_写入前复制` 保留为恒等函数，仅为兼容旧调用点。

推论：任何「靠计数判断是否共享」的机制都不再可靠，也不再需要。

> 真相源：`基础功能/src/运行时/值类型.rs::堆_写入前复制_已锁定`

## 3.3 内存管理

### 3.3.1 模型：引用计数 + 空闲表 + 环收集

| 机制 | 作用 | 边界 |
| :--- | :--- | :--- |
| 引用计数 | 常规回收：计数归零即回收 | **循环引用永不归零** |
| 空闲表 | 回收槽位复用 | — |
| 环收集（L3） | 周期性扫描回收不可达环 | 默认每 2000 次分配触发一次，时机不承诺 |

语言层结论：**内存自动回收，但回收时机不可观测、也不保证发生**（循环引用）。因此语言不提供显式释放语法，也不承诺「实例销毁时回调用户代码」。

### 3.3.2 +1 / −1 的纪律

| 动作 | 含义 | 落点 |
| :--- | :--- | :--- |
| **+1** | 新产生一份**既有**对象的引用（标签别名场景：接口 / 文本 / 函数槽共享、返回值移交、映射读值、结构体接口字段存储） | base 的堆增加引用接口（唯一入口），由前端在明确的「别名」点发射 |
| **−1** | 该局部槽消亡 | 由前端的**拥有型槽清单**驱动，在函数出口统一发出 |
| **move** | 所有权转移，源槽不再释放 | `返回 名称` 记为已移出 |

关键纪律：

- **赋值 / 传参对复合类型是深拷贝**，因此大多数对象没有别名，**不需要**为它们做 +1（否则每层嵌套多一份永不释放的计数）。
- **接口是唯一必须 +1 的共享机制**：接口赋值、接口传参、接口字段存储都要配对 +1。
- **`+1` 与 `−1` 必须同批启用**：只做 −1 会误回收仍被共享的对象；只做 +1 只会泄漏。不存在「先减后补」的中间安全态。

> 真相源：`前端/src/降级/语句转换.rs`（增加引用 / 释放引用发射点）、`基础功能/src/运行时/值类型.rs`（堆增加引用 / 堆释放）

### 3.3.3 统一帧契约（UFC）——内存回收的主体

UFC 把「函数返回时该做什么」收敛成**一次调用**，两个引擎共用：

```
帧消亡(帧):
    相①: 释放   —— 按拥有型槽清单逐槽 −1（级联回收子句柄）
    相②: 清零   —— 把槽位归零，避免陈旧句柄被误读
```

- 释放与清零**分成两相**，中间夹着「读出返回值」，因此返回值不会被提前清掉。
- 解释器与编译器都通过各自的入口调用同一组合语义；编译模式经「影子块」提供帧内的引用型槽镜像。
- **幂等**：悬垂或重复释放静默忽略，不 panic。这让「批量释放与顺序无关」成立。

**拥有型槽清单**（谁进入清单）：

| 进入清单 | 不进入清单 |
| :--- | :--- |
| 函数顶层声明的复合类型局部（创建后转移所有权或深拷贝得到独立对象） | 借用型槽（如 `文本 s = 列表[1]`：元素不深拷贝，槽只是借用） |
| 接口槽（标签别名，已 +1 配对） | `传引用` 形参、`自身` |
| 局部复合类型的返回值（已移交所有权） | 函数参数（借用或已移交） |

**闸门**（清单可用性判定，保守优先）：

| 闸门 | 原因 |
| :--- | :--- |
| 本函数创建了闭包 | 捕获句柄未 +1，放开可能误回收被闭包共享的对象 |
| 本函数出现**接口型数组字面量** | 元素是共享实例，字面量元素当前未逐一 +1 |
| （逐槽路径另有）函数嵌套控制流 | 局部槽复用关系复杂，逐槽判定不可靠 |

原则：**宁可泄漏，绝不误回收**。闸门只放宽「多释放一些」，绝不放松「提前释放」。

> 真相源：`基础功能/src/运行时/值类型.rs::帧消亡`、`帧消亡_释放`、`帧消亡_清零`、`前端/src/降级/函数转换.rs::清单可用`、`前端/src/降级/语句转换.rs`

### 3.3.4 内存可观测

| 手段 | 用途 |
| :--- | :--- |
| `堆统计()` | 存活槽位 / 空闲表 / 回收次数，可作为**双模一致性判据**（两模式统计应一致） |
| `内存.回收()` | 主动触发一次统计扫描与残留清理（**非规范暴露面**，仅诊断用） |
| 帧释放诊断（环境变量开关） | 分类统计「归零回收 / 计数仍大于零 / 槽位缺失」 |

诊断环境变量默认关闭，打开时零额外开销路径。

> 真相源：`基础功能/src/运行时/值类型.rs`、`基础功能/src/运行时/堆操作.rs`

### 3.3.5 注释腐烂警告

内存相关的历史结论（COW、标记清除 GC、清理生命周期方法、动态异常栈）都已退役，但**注释里仍能看到它们的痕迹**。改动内存相关代码时，请同步清理同段的「已停用」注释块，否则后来者会把过期机制当现状。

> 真相源：全仓搜索 `已停用`、`已退役` 注释块

### 3.3.6 所有权细则（谁 +1、谁 −1、谁 move）

| 场景 | 语义 | 计数动作 |
| :--- | :--- | :--- |
| 标量赋值 / 传参 | 直接复制 | 无 |
| 复合类型赋值 / 传参 | **深拷贝**（值语义） | 无需 ±1（各自独立） |
| 复合字面量作为拷贝源 | 拷贝完成后源是临时对象 | 源发 −1（否则字面量临时对象持续泄漏） |
| 接口赋值 / 传参 / 字段存储 | 复制标签（引用语义） | **+1** |
| 读取容器 / 映射元素到局部 | 元素是独立副本 | 视类型而定：复合类型按值语义深拷贝，接口则需 +1 |
| `返回 名称` | 所有权移交 | 源槽**不** −1（记为已移出） |
| `返回 甲.字段` 等复杂表达式 | 不转移所有权 | **保守清空**本函数的释放登记（宁可泄漏） |
| 闭包捕获 | 捕获的是共享句柄 | +1（捕获点） |
| `传引用` 形参 / `自身` | 借用 | 无 |

> 真相源：`前端/src/降级/语句转换.rs`、`前端/src/降级/函数转换.rs`、`基础功能/src/运行时/值类型.rs`

## 3.6 异常机制

### 3.6.1 为什么不用 `setjmp/longjmp`

- 跨语言边界的栈展开不可移植（C++ Itanium ABI 需要额外元数据），与「跨平台 + 可移植产物」的目标冲突。
- 隐式栈展开会让「异常从哪来、到哪去」不可静态推理，调试与审计成本高。

因此智语言采用**显式控制流 + 静态派发目标**（见 2.5.5）。

### 3.6.2 双信号职责契约（不可合并）

| 信号 | 含义 | 载体 |
| :--- | :--- | :--- |
| 待处理 | 当前有异常正在被处理 | 线程局部信号（base 持有真值） |
| 待重抛 | 处理块执行完后需要原样重抛 | 另一个线程局部信号 |

两者**不可合并**：合并后无法区分「错误已处理」与「错误要继续向上抛」，`始终:` 的收尾逻辑会误判。

> 真相源：`基础功能/src/运行时/异常运行时.rs`（两个独立查询 / 置位 / 清除入口）

### 3.6.3 派发：静态目标，不是运行时状态机

每个基本块携带**静态派发目标**（捕获块 / 收尾块 / 外层 / 无）。派发时：

1. 读待处理信号；
2. 若当前块有捕获目标 ⇒ 跳转到它并复位信号；
3. 否则沿调用帧向上传播，直到有人捕获或到最外层（变成未捕获异常）。

后端**不得**另建 finally 状态机——那样会与前端显式流叠加（见 2.5.5 契约 3）。

### 3.6.4 载荷与并发

- 异常载荷在 base 构造（消息 + 标签 + 可选数据），两模式共享同一构造逻辑。
- 任务内的异常跨线程回传：子虚拟机捕获后打包，等待结果时在父侧重抛。
- 异常对象可携带自定义字段；字段访问走统一字段操作码。

> 真相源：`基础功能/src/运行时/异常运行时.rs`、`前端/src/降级/语句转换.rs`

### 3.6.5 失控递归防护（两模常开）

深递归可能导致栈溢出，因此两模式都常开失控递归防护：

- 阈值按构建模式分级（调试档小、发布档大），命中时抛**可捕获**异常（栈溢出 / 执行超限），而不是让进程崩溃。
- 不采用「发布档关闭」的策略：那会让同一程序在两种构建下行为不一致，破坏双模一致性。

> 真相源：`基础功能/src/运行时/异常运行时.rs`、`基础功能/src/公共服务/并发/*`

## 3.7 解释模式：字节码 VM

### 3.7.1 字节码文件格式（V5）

| 项 | 值 |
| :--- | :--- |
| 魔数 | `0x43534C42`（「CSLB」） |
| 版本 | 主 5 / 次 0 |
| 段顺序 | 模块名 → 常量池 → 函数表 → 调试信息 → 代码段 → 异常表 → 拥有型槽段 → 入口函数索引 |

- **代码段是纯寄存器式编码**：每条指令内嵌目标槽与操作数，调用参数内嵌，不需要额外参数缓冲。
- **异常表段**：每函数 `(块起始偏移, 类别, 目标块偏移)`，供静态派发。
- **拥有型槽段**：每函数的拥有型槽索引清单，是 UFC 释放侧的元数据来源。**缺少该段的老文件按「保守不释放」处理**（向后兼容策略：宁可泄漏）。
- **调试信息段**：`(行号, 代码偏移, 列号)` 三元组，供调试器与异常定位。

### 3.7.2 主循环分派

```
函数索引 < 用户函数索引基址          → 系统函数（base::系统调用）
函数索引 ∈ [用户函数索引基址, 65535) → 用户函数（函数表[索引 - 用户函数索引基址]）
```

- `用户函数索引基址` 是常量（当前 400），VM、编译器、降级层一律引用它。
- 上界 `65535` 是历史哨兵，超出即视为非法索引（不做回绕或猜测）。
- 每次系统函数调用计步，用于死循环防护。
- 指令语义全部委托堆操作 / 系统调用；VM 自身只做：取操作数、调用、写结果槽、跳转。

### 3.7.3 帧

- 局部变量表是 `Vec<运行时值>`（32 字节 / 槽），每帧一段；帧起始由局部变量基址标记。
- 弹帧走 UFC：先相①释放，读完返回值后再相②清零。
- 返回值用「带标记操作数」机制，保证能在本帧槽中读出后再清帧。

> 真相源：`后端/解释器/src/字节码格式.rs`、`后端/解释器/src/虚拟机/虚拟机核心.rs`

## 3.8 编译模式：Cranelift

### 3.8.1 统一值表示 ABI

- 每个局部 = `(标签: I64, 载荷: I64)` **双槽**，与运行时值的语义一一对应（追求**语义同构**，不追求机器布局一致）。
- 每个形参 = 两个 `I64`；返回类型为 `空值` 时返回 `void`，否则用 **sret**（首个隐式参数是返回槽指针）。

为什么不直接传 32 字节结构体：Cranelift 的 ABI 对聚合类型按平台约定可能拆分或间接化，跨平台不稳定；双 `I64` 是所有平台都确定的表示。真实运行时值只在调用 base 的 C ABI 边界处按 32 字节解释。

### 3.8.2 两遍结构

| 遍 | 内容 |
| :--- | :--- |
| 第 1 遍 | 为每个 LIR 函数声明符号（`名称_索引`），登记函数名映射 / 返回类型 / 参数个数；扫描闭包与 FFI 回调候选，生成 thunk |
| 第 2 遍 | 逐函数编译：基本块映射、指令翻译、调试信息、影子块 prologue / epilogue |

- **符号名带索引**：避免多模块同名函数在链接期冲突。
- **回调桥 thunk**：编译模式下 FFI 回调不能直接把函数索引交给 C，需生成「按用户函数索引调用」的 thunk 并注册为用户函数调用器。
- **闭包 thunk**：闭包任务与闭包调用用 thunk 地址替代函数索引（存放在堆闭包环境第 0 元素）。

### 3.8.3 影子块（编译模式的内存根）

编译器在**本函数栈帧内**分配一块引用型槽镜像：

- prologue：压入编译帧（影子块地址、槽数、清单指针、清单长度）。**必须先整块清零**——影子块占用复用的栈空间，不清零会把上次调用的残留字节当句柄（轻则对账噪声，重则误 −1）。
- epilogue：弹出编译帧 ⇒ 走 UFC 两相（释放 + 清零）。**所有返回点都必须调用**。
- 清单指针指向产物数据段（编译期常量数组，只读常驻），运行期无需查表。

### 3.8.4 链接

| 平台 | 链接器 |
| :--- | :--- |
| Windows | `rust-lld`（随工具链） |
| Linux / macOS | `cc` |

- 输入：Cranelift 生成的 `.o` + `base.lib`（静态库）+ 外部静态库（FFI shim）+ 外部 C 库 / 导入库。
- 输出：`.exe` / `.a`（静态库模式）/ `.dll|.so|.dylib`（共享模式，FFI 导出块）。
- 共享模式需显式导出符号；导出 thunk 符号名统一前缀。
- 产物自带构建身份标记，运行期与工具链对读（见 5.5.2）。

> ⚠ **已知偏离**：链接器仍直接用 `cfg!(target_os)` 做三平台分支，未收敛到平台抽象（1.5 铁律的例外），登记于附录 E。

### 3.8.5 优化级别

| 命令行 | 级别 | 编号 | 说明 |
| :--- | :--- | :--- | :--- |
| `--调试` | 无优化 | 0 | 保留调试信息，便于定位 |
| （默认） | 速度优化 | 1 | 默认档 |
| `--精简` | 速度与体积 | 2 | 关注产物体积 |

- 编号 `0/1/2` **进入构建签名** ⇒ 同一份源码用不同优化级别编译属于不同产物，缓存不会串。
- 非「无优化」档关闭 Cranelift 的验证器（性能考虑）；`--调试` 保留验证器，便于发现 IR 构造错误。

### 3.8.6 数据段与文本常量

编译模式中「编译期确定、运行期只读」的数据统一放数据段：

| 数据 | 用途 |
| :--- | :--- |
| 文本字面量 | 运行期表现为静态文本（零拷贝，修改时升级为拥有型） |
| 帧释放清单 | 每函数的拥有型槽索引数组；弹帧时直接按切片读 |
| 常量数组 / 类型表信息 | FFI 元数据、导出符号表等 |

> ⚠ **对齐铁律**：写数据段必须 `set_align(8)`。运行期值按 8 字节对齐读取；按 1 字节对齐嵌入会让文本 / 数组落在非对齐地址，产生「只读错值」这类极难定位的故障。

> 真相源：`后端/编译器/src/代码生成/代码生成核心.rs`、`翻译执行器.rs`、`优化管线.rs`、`后端/编译器/src/链接器.rs`

## 3.9 FFI（外部语言互操作）

### 3.9.1 总体形态：生成 shim

不手写 `transmute` 编组，而是由 FFI 代码生成器生成一个小 Rust crate，为每个外部函数生成 `extern "C"` 声明与一个**扁平签名**的包装函数：

```
包装(输出槽指针, 输出槽数, 输入槽指针) -> 运行时值
```

- 编译模式：`rustc --crate-type staticlib` → `.a/.lib`，追加进链接器目标文件。
- 解释模式：`rustc --crate-type cdylib` → `.dll/.so/.dylib`，动态加载并注册包装调度函数。
- **调用点不变**：两模式都走同一系统调用入口与同一份 FFI 元数据，唯一差异是 shim 载体。这正是规范 §6.5.7 定义的「双模功能复用」范式。

### 3.9.2 边界编组

- **值类型透传**：整数 / 小数 / 逻辑 / 指针直接映射。
- **堆对象跨边界**：以「外部值」标签作根标记，把文本 / 数组 / 映射 / 结构体**序列化为扁平缓冲**（每侧自拥堆，边界即序列化点，与 JNI / Python C API 同思路），并配释放入口防悬垂。
- **数组参数**：按「元素精确码 + 紧邻长度参数索引」编组为紧凑缓冲；宿主校验长度上限，调用后按 In / Out 回写。
- **精确 C 类型**：外部块内可用定宽整数、无符号系列、短 / 长小数、字符、指针、函数指针、外部结构体等；编码进 FFI 元数据，跨层契约表见外部调用注册模块。
- **外部结构体**：按 C 表示生成布局，字段用精确码扁平编码，避免「只保留大类」导致位宽丢失。

### 3.9.3 回调

- C 调智语言：注册 trampoline 提供者（预生成若干形状 × 若干槽），经「用户函数调用器」按用户函数索引回调；解释模式传 VM 指针，编译模式传 thunk 地址。
- **必须把用户函数索引与系统函数索引分开**：早期误走系统调用入口，把用户索引当命令码路由。

### 3.9.4 导出方向

`导出:` 块把智语言函数暴露给 C：生成真实 C 签名的 thunk 与头文件，共享模式下链接产物为动态库。

> 真相源：`基础功能/src/运行时/FFI代码生成器.rs`、`外部调用注册.rs`、`回调管理器.rs`、`头文件生成器.rs`

## 3.10 并发与网络

### 3.10.1 并发

| 资源 | 实现 |
| :--- | :--- |
| 通道 | 跨线程通道库，容量 / 关闭语义原生 |
| 任务 | 独立线程跑目标函数，等待即取结果 |
| 终止器 | 原生独立计时线程（不是步数轮询 + 定时器堆） |
| 多路监听 | 原生阻塞选择，前置检查已关闭通道 / 已触发终止器 |

- 并发资源以专门标签表示；解释模式与编译模式使用不同的载荷字段，**构造时两个字段都写**，保证双模一致。
- 任务异常通过打包接口跨线程回传。

### 3.10.2 网络

- TCP / UDP / 流式 / 监听 / HTTP 服务端**全部使用纯 Rust TLS 栈**（已删除 native-tls）：避免在 POSIX 上拖入系统级 OpenSSL 依赖，保持「底层自成一体」。
- HTTP 客户端同样使用纯 Rust 栈。
- 证书与密钥要求**未加密 PEM**；校验可关闭（关闭时使用全接受验证器）。
- **网络等待必须有超时**：否则服务端刚 bind、accept 线程未就绪时客户端会永久阻塞（实测导致门禁挂死并留下孤儿进程占端口）。

### 3.10.3 两种模式的并发执行模型

| 维度 | 解释模式 | 编译模式 |
| :--- | :--- | :--- |
| 任务启动 | 起线程，**独立子虚拟机**跑目标函数 | 生成 thunk（首个隐式参数 = sret 指针），线程调用 thunk 地址 |
| 闭包载体 | 堆闭包环境（函数索引 + 捕获变量） | 同一表示；第 0 元素放 **thunk 地址**替代函数索引 |
| 通道 / 终止器 | 与编译模式同一份实现 | 同左 |
| 模块级变量 | 子虚拟机持有**启动时刻快照**，写入不回写父 | **共享同一内存**，读实时值、写真实生效 |
| 异常回传 | 子虚拟机捕获后打包，等待结果时重抛 | 打包后跨线程回传 |

最后一行是**规范 §7.6 明文承认的唯一双模差异**。规范给出的替代方案是：跨任务交流用参数 / 返回值 / 通道，不要读写模块级变量。

> 不要试图「把解释模式改成共享内存」：那会让子虚拟机与父虚拟机共用堆的同时各自维护帧栈与异常状态，等价于把两个执行引擎耦合在一起，违反分层。**保留差异 + 文档禁止依赖**是与规范一致且成本最低的选择。

> 真相源：`基础功能/src/公共服务/并发/`、`基础功能/src/标准库功能/并发系统函数.rs`、`后端/解释器/src/并发执行器.rs`

## 3.12 第七章内存模型 ↔ 实现逐条对照

规范第七章是**语义契约**（规定「程序可观测到什么」，不规定堆布局、算法与阈值），并明确参照实现为 `值类型.rs`。逐条落地如下：

| 规范条款 | 实现机制 | 关键位置 |
| :--- | :--- | :--- |
| **7.1-R1** 无显式释放语法、无析构 / 终结器 / 清理生命周期方法 | 语言层无任何显式释放语法；清理生命周期方法已**整体删除**（语法 / 语义 / 降级 / 操作码 / 编辑器插件同步移除），现为普通方法名 | 全仓 |
| **7.1-R2** 回收时机不可观测、不保证 | 引用计数 + 空闲表 + 周期环收集；统计扫描只做兜底，**不做可达性分析** | `值类型.rs` |
| **7.2** 值语义 = 深拷贝；接口 / 任意接口 / 传引用 = 只复制标签 | 降级层对**非接口**复合值一律深拷贝（存储 / 赋值 / 传参 / 容器元素）；接口路径复制句柄并 +1 | `语句转换.rs`、`堆操作.rs` |
| **7.2 补充** 隔离是构造性质 | COW 已退役，写入原地进行；隔离完全由「存储即深拷贝」承担 | `值类型.rs` |
| **7.3** 文本不可变，`==` 与 `===` 均值比较 | 文本无写接口；静态文本零拷贝共享，修改时升级为拥有型（语义不可区分） | `值类型.rs` |
| **7.4** 环形引用由运行时回收，时点不承诺 | 环收集：默认每 2000 次分配触发一次，回收不可达环 | `值类型.rs::环收集_按预算` |
| **7.5** 外部资源必须显式释放且放在 `始终:` | `始终:` 由前端发射显式控制流，覆盖正常返回 / 提前返回 / 抛出 / 跳出与继续 | `语句转换.rs`（2.5.5） |
| **7.6** 两模式行为必须一致 | 两引擎共用 base 全局堆与同一套堆操作；内存统计只用于诊断 | 3.1 / 3.3 |
| **7.6 例外** 任务内读 / 写模块级变量属实现相关 | 规范明文承认：解释模式 = 任务启动快照，编译模式 = 实时共享内存 | `并发执行器.rs` |
| **7.7** 允许保守推迟回收，绝不提前回收 | 清单闸门仅对「接口型数组字面量 / 本函数创建闭包」整函数禁用；借用型槽不入清单；异常传播延迟到弹帧 | `函数转换.rs::清单可用` |
| **7.7 唯一硬保证** 永不访问已释放对象 | 代际句柄（陈旧句柄解码失败）+ 释放幂等 + 根枚举对账（悬垂即致命） | `值类型.rs` |

### 3.12.1 三条容易被误解的点

1. **「自动管理」不等于「GC」**：语言确实不暴露释放语法，但实现是引用计数 + 环收集，不是追踪式 GC。「回收时机不可观测」因此是**结构性事实**，不是文档措辞。
2. **「值语义」不是「写入时分离」**：COW 退役后，复合类型赋值当场深拷贝，「改副本影响原对象」在构造上不可能——比「写入时判断计数」更可靠（后者曾因计数虚高而误分离）。
3. **并发例外是规范明确让步**：不要在实现里「修好」它，那等于改变语言语义；正确做法是文档与诊断提醒用户不要依赖。

### 3.12.2 非规范暴露面（实现多出来的 API）

| 接口 | 规范状态 | 建议 |
| :--- | :--- | :--- |
| `内存.回收()` | 规范未定义该模块 | 仅用于诊断与测试脚本；用户程序一旦依赖它，就依赖了 R2 明文禁止的行为 |
| 堆统计 / 帧释放诊断 / 环收集日志 | 运行时诊断设施 | 可作为双模一致性判据，但不属语言接口 |

## 3.13 双模差异的完整清单

规范允许的差异只有「任务体内访问模块级变量」一项。除此之外，任何差异都是缺陷。容易产生**假差异**的三类：

| 现象 | 是否真差异 | 判据 |
| :--- | :--- | :--- |
| 编译模式输出为空 / `通过：0 失败：0` | 通常不是 | 用 `运行 --编译模式` 直接跑，看 stderr 与退出码（5.6.3） |
| 输出多了工具链日志行 | 不是 | 编译日志，对比时滤掉 |
| 并发 / 网络用例时序不同 | 通常不是 | 必须设超时、避免依赖调度顺序 |

> 判据顺序永远是：**先排除观测口径，再怀疑语义**。历史上多次把「门禁口径」误判成「编译侧崩溃」，代价是数轮排查。

# 第四部分 标准库与核心库

> 本部分只讲**结构与治理**：库怎么被声明、怎么被发现、怎么保证「声明的」与「实现的」不漂移。具体函数签名与语义以《智语言编程规范》第四、五章为准。

## 4.0 本部分导读

- **4.1** 三层划分：核心库、标准库、第三方库各自负责什么。
- **4.2** 元数据是唯一真源；门面由它机械生成。
- **4.3** 四层校验把「文档漂移」变成红灯。
- **4.4** 新增一个库函数的完整清单（照着做就不会漏）。
- **4.5** 数学 5 个内建结构体：为什么它们不是「普通结构体」。
- **4.6** 七个标准库模块的实现矩阵。

## 4.1 三层划分

| 层 | 导入方式 | 内容 | 实现位置 |
| :--- | :--- | :--- | :--- |
| **核心库** | 免导入、语言内建 | 8 个全局函数、容器与文本方法、类型判断、运算符 | `base/核心库功能/*` + `堆操作` |
| **标准库** | 免声明，按模块名直接使用 | 七个模块（工具、并发、数学、文件、时间、网络、系统）+ 内存 | `base/标准库功能/*` + `前端/src/标准库元数据.rs` |
| **第三方库** | `导入 库名/模块路径` | 外部发布的库 | 用户项目 + 库管理 |

8 个全局函数的系统函数索引**不连号**，切勿在分派处硬编码数字：

| 函数 | 索引 | 函数 | 索引 |
| :--- | :--- | :--- | :--- |
| `输出` | 0 | `类型` | 4 |
| `转文本` | 1 | `异常错误` | 5 |
| `转整数` | 2 | `转小数` | 116 |
| `输入` | 3 | `错误输出` | 179 |

> 真相源：`基础功能/src/核心库功能/核心系统函数.rs`、`基础功能/src/标准库索引.rs`

## 4.2 元数据：唯一真源

| 概念 | 位置 | 角色 |
| :--- | :--- | :--- |
| **元数据** | `前端/src/标准库元数据.rs` | **唯一真源**：每个库函数的名称、所属模块、形参、默认值、返回类型 |
| **实现** | `base/标准库功能/*.rs` | 按元数据登记的索引实现语义 |
| **门面** | `源码/标准库/*.智` | 由元数据**机械生成**的智语言源码，仅供人读与校验，禁止手改 |

三条不变量：

1. **索引只在元数据登记一次**，运行期按索引分派；实现文件按同一索引写处理分支。
2. **门面不得手写**：手写即与元数据产生第二份声明，必然漂移。
3. **签名对照表**（`前端/src/规范签名.rs`）单独登记需要与规范逐字核对的函数签名（当前覆盖系统、时间两个模块），用于发现「实现与规范不一致」。

> 真相源：`前端/src/标准库元数据.rs`、`前端/src/标准库门面生成.rs`、`前端/src/规范签名.rs`

## 4.3 四层校验（真源门禁）

| 层 | 校验内容 | 失败后果 |
| :--- | :--- | :--- |
| 元数据 ↔ 实现 | 索引一致性与覆盖（自检在启动期 fail-fast） | 启动即报错，不等到调用时 |
| 元数据 ↔ 门面 | 名称、模块归属、签名、默认值逐项比对 | 门禁红灯 |
| 元数据 ↔ 规范 | 签名对照表逐字比对 | 门禁红灯 |
| 命名 ↔ 规范 | 路径级命名检查（文件名、目录名） | 门禁红灯 |

设计要点：**把「人会不会记得同步」换成「机器会不会发现不一致」**。这是本项目对付「两份手写声明」的根本手段。

> 真相源：`前端/src/标准库真源校验.rs`、`前端/src/标准库元数据.rs`、`pm/src/命名规范.rs`

## 4.4 新增一个标准库函数的完整清单

| # | 步骤 | 落点 |
| :--- | :--- | :--- |
| 1 | 在规范里写清语义与签名 | 《智语言编程规范》第五章 |
| 2 | 在元数据里登记：名称、模块、形参、默认值、返回类型 | `标准库元数据.rs` |
| 3 | 在对应后端文件里按**同一索引**实现处理分支 | `base/标准库功能/*.rs` |
| 4 | 若索引落在新号段，**同步更新分发器区间委托** | `base/运行时/分发器.rs` |
| 5 | 重新生成门面（禁止手改门面） | `标准库门面生成.rs` |
| 6 | 跑四层校验 + 双模用例 | 见 5.6 |

第 4 步是最容易漏的一步：只加索引不加委托 ⇒ 函数静默返回空值。

> 真相源：`前端/src/标准库元数据.rs`、`基础功能/src/标准库功能/`、`基础功能/src/运行时/分发器.rs`

## 4.5 数学 5 个内建结构体

规范第五章定义了五个内建数值结构体：精确小数、短小数、无符号整数、字节、无限整数。

| 项 | 事实 |
| :--- | :--- |
| 类型索引 | 11 ~ 15（用户结构体基址从 16 起） |
| 前端职责 | 只在类型推导里登记类型、字段、方法表、运算符重载与构造重定向 |
| 运算实现 | 全部由 `base` 的数学系统函数用 Rust 原生类型实现，经系统调用分派 |
| 门面 | 按规范写出结构体壳子（结构体形参 + 私有字段 + 初始化方法 + 方法） |
| 双模差异 | 无：前端只登记，执行路径与普通方法调用相同 |

三条工程注意：

1. **不要在文档里抄方法条数**——会随补登记漂移；以规范与元数据为准。
2. **类型名必须统一**：注册名与用户可见名要能互相映射，否则方法查找与约束判定会不一致。
3. **精确小数的缩放约定是契约**：加减取较大缩放，乘除 clamp 并舍入，越界抛具名异常。

> 真相源：`前端/src/语义/类型推导.rs`、`基础功能/src/标准库功能/数学系统函数.rs`、`基础功能/src/运行时/值类型.rs`

## 4.6 标准库七个模块的实现矩阵

| 模块 | 后端 | 接线方式 | 要点 |
| :--- | :--- | :--- | :--- |
| 工具 | 工具系统函数 | 带 `处理X` | 哈希、正则、数据解析等；解析结果返回裸动态值 |
| 并发 | 并发系统函数 | **helper 型**（无独立处理函数，由核心后端调用） | 通道 / 任务 / 终止器 / 多路监听；批量等待走专用操作码，不经系统函数索引 |
| 数学 | 数学系统函数 | 带 `处理X` | 五个内建结构体的运算与转换 |
| 文件 | 文件系统函数 | 带 `处理X` | 路径、读写、目录、编码 |
| 时间 | 时间系统函数 | 带 `处理X` | 时间戳、格式化、单调计时器 |
| 网络 | 网络系统函数 | 带 `处理X` | TCP/UDP/HTTP/TLS；等待必须有超时 |
| 系统 | 系统底层函数 | 带 `处理X` | 平台相关的基础能力，经平台抽象收敛 |

「两种接线方式」的区别见 3.5：**带 `处理X` 的后端必须补区间委托臂**，漏了就会静默返回空值。

> 真相源：`基础功能/src/标准库功能/`、`基础功能/src/运行时/分发器.rs`

# 第五部分 工程体系与工具链

> 本部分回答「用户怎么用、产物怎么来、测试怎么跑、发布怎么打包」。

## 5.0 本部分导读

- **5.1** 工作区与四个二进制（引导程序与工具包分离）。
- **5.2** 命令面：18 个命令与它们的输入 / 产物。
- **5.3** 目录与配置：全局、项目、产出三类路径。
- **5.4** 库管理：封装、注册表、镜像与中文域名。
- **5.5** 缓存与构建身份：指纹驱动的失效判定。
- **5.6** 测试体系：门禁、判定口径与假绿风险。
- **5.7** 发布：便携版与自解压安装包。
- **5.8** 编辑器服务：独立进程的语言服务。

## 5.1 工作区与二进制

| crate | lib 名 | 职责 |
| :--- | :--- | :--- |
| 前端 | `frontend` | 词法 → 语法 → 语义 → 降级 |
| 基础功能 | `basic_functions`（lib 名 `base`） | 运行时真相（静态库 + rlib） |
| 解释器 | `interpreter` | 字节码生成 + 虚拟机 |
| 编译器 | `compiler` | Cranelift 代码生成 + 链接 |
| 项目管理 | `pm` | 配置、目录、依赖解析、命名规范、网址规范化 |
| 库管理 | `libmgr` | 库安装 / 解包 / 发布 |
| 版本管理器 | `launcher` | **4 个 bin** + lib |
| 编辑器服务 | `editor_service` | LSP（**独立 EXE**） |
| 模拟服务器 | `mock_server` | 网络测试用模拟服务 |

四个 bin：

| bin | 源 | 职责 |
| :--- | :--- | :--- |
| `智语言` | `主程序.rs` | **引导程序**：读全局配置 → 解析项目声明的工具包版本 → 在安装路径匹配已装版本 → 转发执行（设环境变量防递归） |
| `智语言开发套件` | `命令行入口.rs` | 业务命令本体 |
| `产出发布` | `产出发布.rs` | 打包便携版 / 安装包 |
| `智语言安装程序` | `安装程序.rs` | 自解压安装器 |

两条架构决定：

- **引导程序与工具包本体分离**：引导程序不实现业务命令，只做「版本选择 + 转发」，从而支持多版本共存，用户 PATH 里只需一个 `智语言`。
- **编辑器服务是独立 EXE**：不合并进开发套件，也不通过子命令启动。理由是进程模型不同（长期驻留、stdio 协议、崩溃不应拖垮 CLI）。

> 真相源：根 `Cargo.toml`、`源码/版本管理器/Cargo.toml`、`源码/版本管理器/src/主程序.rs`

## 5.2 命令面

`智语言 <命令> [参数]`，共 18 个（`命令行入口.rs` 是唯一路由表）：

| 类别 | 命令 |
| :--- | :--- |
| 执行 | `运行` `构建` `构建运行` `交互` |
| 质量 | `检查` `格式化` `测试` `基准` |
| 工程 | `创建` `清理项目` `清理全局` `生成关联` `生成门面` |
| 生态 | `库` `账号` |
| 其他 | `文档` `版本` `帮助` |

命名约定：**编译 → 构建**、编译运行 → **构建运行**，旧名不保留别名。

常用开关：

| 开关 | 作用 |
| :--- | :--- |
| `--编译模式` | 走编译模式（默认解释模式） |
| `--跳过缓存` | 忽略缓存，强制重编 |
| `--直接执行` | 纯解释，不落字节码文件 |
| `--重新编译` | 强制重新编译（连编译中间产物一起重做） |
| `--简洁` / `--颜色` / `--结构化` | 诊断输出形态 |

> **`测试` 与 `运行` 的观测面不同**：`运行` 直连程序、输出即所见；`测试` 会加夹具与汇总行。排查「输出缺失 / `通过：0 失败：0`」这类现象时，必须先用 `运行`（及 `运行 --编译模式`）交叉复核，再回到门禁口径。

### 5.2.1 命令 → 输入 / 产物 / 代码位置（节选）

| 命令 | 输入 | 产物 | 关键代码 |
| :--- | :--- | :--- | :--- |
| `运行 <文件>` | 单文件 | 字节码文件（`--直接执行` 不落盘） | `命令/运行命令.rs` + `缓存管理.rs` |
| `运行`（无参） | 项目入口 | 同上 | 同上 + `pm/项目源文件.rs` |
| `构建 <文件>` | 单文件 / 项目 | 对象文件 → 执行文件（库模式为静态库；导出模式为动态库） | `命令/编译命令.rs` + `链接器.rs` |
| `构建运行` | 同上 | 同上 + 执行产物（透传 stdout 与退出码） | 同上 |
| `测试 <文件>` | 测试文件 | **无产物**（字节码在内存） | `命令/测试命令.rs` |
| `测试 <文件> --编译模式` | 测试文件 | 临时夹具可执行文件（跑完删除） | `命令/测试辅助.rs::合成测试启动程序` |
| `检查` | 源码 | 无（只输出诊断） | `命令/质量命令.rs` |

### 5.2.2 测试的两种执行模型（差异的根源）

| 维度 | 解释模式 | 编译模式 |
| :--- | :--- | :--- |
| 执行单位 | **逐个测试函数**在同一个进程内调用 | **合成夹具**：生成一个启动程序遍历全部测试函数并打印统一 RESULT 行，编译成独立可执行文件后执行一次 |
| 输出形态 | 每个函数的结果行 + 汇总行 | 夹具输出 + 汇总行 |
| 成本 | 每例 < 1 秒 | 每例需编译 + 链接（秒级） |
| 适用 | 高频迭代、快速定位 | 发布前、双模对账 |

两条必须知道的配套事实：

1. **编译模式也先跑语义分析预检**：否则负向用例在编译模式可能因「根本没走到编译」而输出 `通过：0 失败：0`，被门禁当成通过。
2. **逐函数执行时必须先跑模块级初始化序列**：否则测试函数里 `本模块.X` 读到空值，与编译模式产生假分歧。

> 真相源：`源码/版本管理器/src/命令/测试命令.rs`、`测试辅助.rs`

## 5.4 库管理

命令族：`安装` / `卸载` / `更新` / `封装` / `发布` / `搜索` / `信息` / `已安装` / `查看依赖`，以及 `全局 安装` / `全局 卸载` / `全局 已安装`。

| 能力 | 要点 |
| :--- | :--- |
| 封装 | UTF-8 ZIP，`.库` 后缀；默认**剔除**运行期无用文件（符号与中间产物、头文件目录、包配置目录、构建脚本目录），保留三平台动态 / 静态库与共享资源；逃生舱开关可保留全部 |
| 传递外部语言依赖 | 库自包含外部语言依赖；安装时把锁文件路径改写为库内路径，消费方**无需**声明 |
| 注册表 | 本地文件注册表（扫描全局库目录 + 索引文件）+ 远程 HTTP 客户端；无服务器时**明确报错**，不留占位实现 |
| 镜像 | 镜像源配置；取源地址是唯一出口 |
| 中文域名 | 官方源是 IDN ⇒ 项目管理模块手写 Punycode 与 IDNA 转换（**只转主机名**，路径编码仍归各客户端） |

> IDN 这一条是踩过的坑：HTTP 客户端按 RFC 3986 只接受 ASCII 主机名，默认配置域名本身是中文 ⇒ 所有远程请求报「非法 URI 字符」。由于问题在**默认配置**而非用户输入，必须在「取源地址」这一处统一规范化。

> 真相源：`源码/项目管理/src/`、`源码/库管理/src/`、`pm/src/网址规范化.rs`

## 5.5 缓存与构建身份

### 5.5.1 缓存键

| 模式 | 键 |
| :--- | :--- |
| 解释 | 源集合哈希 \| 激活版本 \| 前端指纹 \| 基础指纹 \| 解释器指纹 |
| 编译 | 上述 + 编译选项 \| 平台 \| 静态或动态 \| 编译器指纹 |

任一分量变化即失效。**不需要人工 bump 版本号**（`编译器逻辑版本` 常量仅用于人类可读展示）。

### 5.5.2 base.lib 新鲜度

- 链接器判定 `base.lib` 是否新鲜，不再用 mtime 启发式，而是**从产物字节读出**构建身份标记与当前基础指纹比对。
- 工具可执行文件内嵌同一标记 ⇒ 安装包闸门能拒绝「版本号相同但 base 已变」的打包。
- 好处：debug / release 交叉、复制粘贴产物、时钟错乱，都不会再造成「用了旧 base」。

> 部署提醒：手工替换二进制时，必须让 `base.lib` 与工具可执行文件的指纹一致，否则会拒链（这是设计意图，不是缺陷）。

> 真相源：`源码/版本管理器/src/构建签名.rs`、`源码/后端/编译器/src/链接器.rs`

## 5.6 测试体系

### 5.6.1 目录约定

| 目录 | 用途 |
| :--- | :--- |
| `测试/1单个代码文件测试/` | 单文件用例 |
| `测试/2项目类测试/` | 项目级用例（含外部库、多模块） |
| `测试/3测试脚本/` | 门禁脚本 |
| `日志/脚本/` | 脚本输出（镜像结构）；`日志/脚本/临时/` 放单例中间文件，跑后可一键清理 |

### 5.6.2 门禁脚本的三条铁律

1. **每个文件限时**（默认 20 秒快失败，上限约 120 秒，打包 / 构建类可放宽）：超时即判定「内容有问题」，不要干等。
2. **必须校验子进程退出码**：只看标准输出会把「崩溃但打印了一半」判成通过。
3. **不要用 `Start-Process -PassThru` 而不 `-Wait` 取退出码**（不可靠）；用进程对象 API，且异步读取必须在等待退出**之前**启动，否则管道缓冲满即死锁。

### 5.6.3 假绿（false pass）风险清单

这是本项目最需要警惕的一类问题——**门禁通过但功能是坏的**：

| 风险 | 表现 | 防法 |
| :--- | :--- | :--- |
| 编译模式输出不回打 | 断言失败但退出码为 0，门禁只看到 `通过：N 失败：0` | 编译模式**始终回打**程序输出，并滤掉工具链日志行 |
| 子进程退出码未校验 | 产物崩溃仍判通过 | 显式检查退出码 |
| 期望失败 vs 真崩溃 | 负向用例「报错了」就被当通过 | 断言**错误类型或文案**，不只断言「非零退出」 |
| 产物过期 | 用旧产物跑出新结论 | 跑前比对产物与源码时间戳，或用构建指纹 |
| 夹具孙进程孤儿 | 超时只杀父进程，孙进程占端口 | 杀进程树；网络用例必须设超时 |
| 文件名编码 | 中文脚本名 / 参数在 PowerShell 下乱码 | 脚本存 UTF-8 **带 BOM**；中文路径优先用 Python 脚本（宽字符原生） |

### 5.6.4 判定「是否本次引入」的方法论

必须做**开启 / 关闭对照实验**：同一改动前后各跑一遍门禁，比较失败集合是否完全一致。只看「有 4 个失败」就归因于本次改动，历史上多次误判。

### 5.6.5 负向用例：`@预期错误` 与 `@期望包含`

「必须报错」的规范条款用正向用例测不出来，因此用例文件头部有一个注释级约定：

| 注解 | 含义 |
| :--- | :--- |
| `@预期错误 <说明>` | 本用例**应当**失败；说明写清违反哪条规范 |
| `@期望包含 <片段>` | 输出**必须包含**该片段；可同行写，也可「注解独占一行 + 片段写在下一行注释」 |

判定实现在测试脚本目录的判定脚本里，**唯一一份**，多个门禁共用；各门禁只保留自己的「运行命令」，判定口径不再各自漂移。判定顺序**不可调换**（错误优先于 `通过：`，否则 `通过：0` 汇总行会让报错用例误判通过）：

1. 有 `@预期错误` ⇒ 必须**确实**出错（错误标志命中，或退出码非零）；否则判失败（预期错误未触发）。
2. 有 `@期望包含` ⇒ 输出必须含该片段，否则判失败（期望错误未出现）。
3. 无 `@期望包含` ⇒ 任何错误即通过，但**拒绝脚手架级无关错误**（如「与内建标准库冲突」「程序入口重复定义」「未找到测试函数或启动程序」「panic」「编译错误前缀」）。理由：负向模板叠加出两个启动程序时，实报「入口重复定义」，与用例本意毫无关系，旧口径照样判通过。
4. 正向链：无测试内容 → 网络特例（可选）→ 错误标志 / 退出码 → `通过：N / M` 且 N<M 直接失败 → `通过：N`（N ≥ 1）。
5. 兜底：无错误、无标记、退出码 0 ⇒ 视为通过（演示 / 入口类用例）。

两条配套事实：

- **错误标志词表里没有裸 `异常错误`**：它是合法的全局函数名与内建类型名，进词表会把正常打印该名字的用例误判失败。
- 判定脚本必须与门禁脚本**同编码**保存，否则中文脚本名与参数会乱码。

### 5.6.6 权威入口与脚本碎片治理

- `测试/3测试脚本/门禁使用规范.md` 规定目录、命名、**权威入口**与日志落位。判定逻辑只允许一份；门禁之间的差异只应体现在「运行什么命令」，而不是「怎么判」。
- 超时口径：批量跑用例的脚本逐文件限时**默认 20 秒**（快失败，避免死循环用例吃满整机）；确需更长用环境变量放宽，上限约 120 秒（2 分钟跑不完即判定内容有问题；构建 / 打包类可适当放宽）。超时单独复测，不阻塞后续用例。
- `输入()` 类用例必须喂标准输入（约定同目录放 `<用例名>.输入.txt`），否则读到 EOF 会变成假失败。
- 回环 / 网络类用例必须设连接超时，且门禁结束进程要用**进程树**（否则夹具孙进程变孤儿占端口，制造「下一例莫名失败」）。

## 5.7 发布

```
产出发布 → 便携版 ZIP（含 base.lib、标准库、工具链）
         → 安装包 = 便携版 ZIP 追加到安装程序 exe 末尾（自解压）
```

发布闸门：

- `base.lib` 与工具可执行文件的构建身份标记必须一致，否则拒绝打包。
- 便携版**必须含 `base.lib`**（漏掉会导致「解压后无法编译」）。
- 版本号唯一真相源：版本管理器的 `Cargo.toml` 的 `version`；发布包名、版本目录、压缩包内的版本目录全部跟随。

> 真相源：`源码/版本管理器/src/产出发布.rs`、`安装程序.rs`

## 5.8 编辑器服务（LSP）

`源码/编辑器服务`（`editor_service`，**独立 EXE**）通过 **stdio + JSON-RPC** 提供语言服务。

| 文件 | 职责 |
| :--- | :--- |
| `主程序.rs` | LSP 主循环：初始化握手、能力声明、请求分发 |
| `位置映射.rs` | 字节偏移 ↔ 行列 ↔ LSP 位置（UTF-16 码元）三向换算 |
| `符号与引用.rs` | 从语义层符号表抽取符号与引用位置 |
| `定义跳转.rs` | 同文件内跳转 |
| `跨文件跳转.rs` | 跨模块跳转（靠模块加载器的导入图定位目标文件） |
| `悬停.rs` | 悬停信息：类型 / 签名 / 文档注释 |
| `成员解析.rs` | `对象.` / `模块.` 之后的候选成员补全 |
| `缓存.rs` | 文件内容与分析结果缓存 |

三条架构约束：

1. **不与开发套件合并**，不提供子命令入口（进程模型不同）。
2. **不重写语言逻辑**：直接复用前端与项目管理模块，因此**编辑器看到的语义与编译器完全一致**——这是「双模一致」在工具链侧的延伸。
3. **不产出构建产物**：只做分析，不写字节码 / 目标文件，也不执行用户程序。

> 位置映射是最容易出错的一环：编辑器的位置用 **UTF-16 码元**，Rust 侧是 UTF-8 字节 + 字符。中文标识符在两者之间换算必须走位置映射模块，不能在业务代码里直接做「字节偏移 + 1」。

> 真相源：`源码/编辑器服务/src/`

| 6 | `基础功能/src/运行时/` | 真实运算语义（除零、取余符号、溢出策略） |

### 6.1.8 改 ±1 落点或拥有型槽判定（内存）

- 三类落点必须一起动：**拥有型槽清单**、**弹帧释放**、**存储侧 +1**。
- 判据变更后依次跑：内存回归（存活槽位不随迭代增长）→ 结构体项目门禁 → 双模对账 → 释放诊断分类计数（归零回收 / 计数仍大于零 / 槽位缺失）。
- **借用型槽绝不能进清单**（如 `文本 s = 列表[1]`，元素不深拷贝），否则会回收掉容器仍持有的对象。
- **−1 必须有配套 +1**：单边启用只会得到「悬垂」或「泄漏」二者之一，不存在中间安全态。

## 6.2 双模一致性：怎么验

### 6.2.1 三层一致性判据

| 层 | 判据 | 手段 |
| :--- | :--- | :--- |
| 语义层 | 两模式**同一份前端**产出同一份 LIR | 共享前端本身就是判据 |
| 运行时层 | 两模式**同一套 base** 语义 | 内存统计、容器行为、异常文案 |
| 产物层 | 两模式**可观察行为**一致 | 差分对账（输出 + 退出码） |

### 6.2.2 差分对账流程

1. 对每个用例分别跑解释模式与编译模式，采集 `(输出, 退出码)`。
2. 与**基线差异集**比较，而不是两两互比——这样新增分歧与历史分歧能分开。
3. 差异条目必须逐条归类：真差异 / 观测口径 / 环境问题。
4. **判定「是否本次引入」必须做开启 / 关闭对照**（见 5.6.4）。

### 6.2.3 常见假分歧

| 现象 | 根因 | 处理 |
| :--- | :--- | :--- |
| 编译模式输出为空 | 产物未生成或已崩溃 | 用 `运行 --编译模式` 直跑，看 stderr 与退出码 |
| 输出多出工具链日志行 | 编译日志混入 | 对比时滤掉 |
| 负向用例两模式都「通过」但行为不同 | 判定口径只看「有没有错」 | 加 `@期望包含` 精确断言 |
| 网络用例时序不同 | 未设超时 / 依赖调度顺序 | 设超时、消除顺序依赖 |

## 6.3 代码协作规范

### 6.3.1 注释保鲜

- **改机制时顺手 grep 该机制的名字**，把描述旧机制的注释一并更新或删除；确需保留历史痕迹的，标注「（已停用 · 日期 + 原因）」。
- 注释解释**为什么**，不解释**是什么**（「是什么」由代码本身与真相源文档承担）。
- 任何「以后会实现」「暂时不支持」的注释必须同时登记到附录 E，否则读者会当成已支持。

### 6.3.2 评审要点

| 检查项 | 判据 |
| :--- | :--- |
| 是否引入了新的魔数 | 应改为引用既有常量 |
| 是否在引擎里写了类型分派 | 应下沉到 base 或在语义层定案 |
| 是否新增了「第二份声明」 | 应改为元数据单一真源 + 机械生成 |
| 是否漏了分发器区间委托 | 新增系统函数索引必查 |
| 是否破坏了 ±1 配对 | 内存相关改动必查 |
| 是否留有描述旧机制的注释 | 按 6.3.1 清理 |

## 6.4 三条单源红线（违反即事故）

```
① 索引单源   系统函数号 / 用户函数基址 / 结构体类型基址 —— 只有常量，没有魔数
② 语义单源   容器分派 / 算术 / 比较 / 异常构造 / 索引规则 —— 只在 base
③ 布局单源   运行时值 32 字节 / 字节码段格式 / HIR 与 LIR 节点 —— 只有一处定义
```

三条红线的共同判据：**同一事实只允许有一个定义位置**。违反不会立刻报错，但会让「改一处、忘另一处」变成常态——而这正是历史上绝大多数事故的来源。

| 构建指纹 | 源树内容哈希，驱动缓存与基础库新鲜度 |
| 单表 | 操作码 → base 堆操作的**唯一**映射表，两引擎都经它委托 |
| P0 安全网 | 编译器对「前端发射但后端无真实处理器」的操作码**编译期拒编**，禁止静默产出空值 |
| 索引空间 | 跨 crate 契约：系统函数号段、用户函数基址、内建结构体类型号段、用户结构体基址 |
| 结果槽 | 寄存器式指令的目标槽；**任何指令都必须有**，否则解码错位 |
| 代际（句柄） | 句柄 = 代际 + 索引；槽位复用时代际 +1 ⇒ 陈旧句柄静默失效 |
| 环收集 | 周期检测回收互相引用的环；默认每 2000 次分配触发 |
| 夹具 | 编译模式测试合成的启动程序：遍历测试函数并打印统一结果行后编译执行 |
| 双模对账 | 同一用例分别走解释与编译，逐例比对输出与退出码，并与基线差异集比较 |
| 假绿 | 门禁判通过但功能实际是坏的 |
| 负向用例 | 头部写 `@预期错误` 的用例：**必须失败**才算通过 |

## 附录 C 与业界方案对照

| 本项目 | 业界对应 | 差异 |
| :--- | :--- | :--- |
| 三层模型（语义单源 / 契约单源 / 引擎双实现） | CPython + JIT、Lua + LuaJIT、JVM 解释器 + C2 | 一致：引擎双实现不可避免，语义单源是可达上限 |
| 显式控制流异常（无 `setjmp`） | C++ Itanium 两阶段（搜索 / 展开分离） | 本项目用「静态目标 + 线程局部标志」，因可移植性与可推理性 |
| 引用计数 + 空闲表 + 环收集 | Swift ARC、Rust `Rc` + 周期检测 | 一致：循环引用靠额外机制；代价是回收时机不可观测 |
| 编译期插桩 + 运行时计数 | Swift ARC（编译器插桩 + 运行时 retain / release） | 一致：本项目把 +1 下沉到 base，−1 由前端清单驱动 |
| 元数据单一真源 + 机械生成门面 | Python `builtins`、`@IntrinsicCandidate` | 本项目多一道机械校验，把文档漂移变成红灯 |
| FFI 边界即序列化点 | JNI、Python C API、Lua C API | 一致：每侧自拥堆 |
| 全中文实现命名 | 无先例 | 独有；代价是英文生态工具（lint / 搜索）适配成本 |

## 附录 D 常见故障排查

| 症状 | 优先怀疑 | 动作 |
| :--- | :--- | :--- |
| 功能「没实现」（返回空值） | 分发器区间漏登记 | 查分发器匹配是否覆盖该索引 |

| 编译模式有输出而解释模式没有（或反之） | 语义分叉到引擎 | 查是否在某引擎内写了类型分派 |
| `通过：0 失败：0` | 编译产物未生成或已崩溃 | 用 `运行 --编译模式` 直跑，看 stderr 与退出码 |
| 内存持续增长 | 拥有型槽清单为空 / 借用槽误入 / 环 | 堆统计 + 释放诊断 + 环收集日志 |
| 弹帧后访问崩溃 | 先清零后释放 / 清单含借用槽 | 检查是否绕过帧消亡组合入口 |
| 字段修改不跨调用保留 | 值语义深拷贝 与 接口共享的差异 | 确认该类型是值语义还是接口（2.3.12） |
| 缓存命中旧结果 | 指纹未覆盖改动 | 用 `--跳过缓存` / `--重新编译` 定位 |
| 链接失败（未解析符号） | 增量编译缓存损坏 | 清理对应 crate 后重建 |
| 链接失败（可执行文件被占用） | 残留进程 | 先结束进程再重建 |
| 循环一次都不执行 | 循环引导词笔误被当类型标注 | 看语法层是否有对应纠正诊断（2.2.5） |
| 一元表达式抛异常 | 一元运算符绑定了比较 | 一元最小优先级必须是 100（2.2.6） |
| 负向用例「报错了」却与本意无关 | 脚手架级错误顶替 | 补 `@期望包含` 精确断言（5.6.5） |
| 表达式分组与预期不同 | 属于与比较的相对优先级、幂的左结合 | 显式括号；口径见 2.2.6 |
| 接口变量指向的对象被提前回收 | 标签别名漏 +1，或该槽被当成借用型 | 查增加引用的发射点（3.3.2） |
