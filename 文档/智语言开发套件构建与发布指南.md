## 一、仓库结构与三个可执行文件

本仓库（`智语言/`）是一个 Cargo 工作区，核心 crate 为 `源码/版本管理器`（package 名 `launcher`），它产出三个可执行文件：

| 可执行文件 | 角色 | 说明 |
|---|---|---|
| `智语言` | 引导程序（统一入口） | 版本匹配、命令转发、安装/更新 |
| `智语言开发套件` | 开发套件本体 | 运行/构建/测试/创建/库 等业务命令 |
| `产出发布` | 发布打包器 | 把构建产物打包为发布文件（安装包/便携版/校验） |

> 各子 crate：`源码/基础功能`（底层真相库 base）、`源码/前端`、`源码/后端/解释器`、`源码/后端/编译器`、`源码/项目管理`、`源码/库管理`。

## 二、环境要求

- Rust 工具链（`cargo`，edition 2021，建议最新稳定版）。
- 操作系统：Windows / macOS / Linux（全平台支持；Windows 下为 `.exe`，POSIX 下无后缀）。
- 首次构建需联网拉取 crates.io 依赖；完全离线见「五、离线构建」。

## 三、构建（只需 cargo 命令）

在仓库根目录 `智语言/` 下执行：

```sh
# 调试版（日常开发；[profile.dev] opt-level=1 为既定设置，勿改回 0）
cargo build --bin 智语言开发套件

# 发布优化版
cargo build --release --bin 智语言开发套件
```

产物位置（构建目标目录已由 `.cargo/config.toml` 固定为 `产出/`，**不要**改用默认 `target/`，否则会丢失 base 静态库链接与缓存指纹）：

- 调试版：`产出/debug/智语言开发套件.exe`（POSIX 为无后缀同名文件）
- 发布版：`产出/release/智语言开发套件.exe`

三个 bin 都可以单独构建：`cargo build --bin 智语言`（引导程序）、`cargo build --bin 产出发布`（打包器）。全部构建：`cargo build`。

> **为什么不需要构建脚本**：`cargo` 命令本身就是完整构建流程。`脚本/` 下的构建脚本只是作者本机的便利包装（例如规避某些终端中文参数编码问题的 `.py` 包装），对外部贡献者毫无必要。

## 四、安装与更新到全局（可选）

构建出的 exe 可直接使用；若要安装为全局命令（任意目录可用 `智语言`）：

```sh
# 把某个发布 zip 安装进全局目录（支持本地 zip / tar.gz 路径）
智语言 安装 <发布包.zip>

# 已安装环境下自更新
智语言 自我更新
```

全局目录规范：Windows `%LOCALAPPDATA%/智语言/`、Linux `~/.智语言/`、macOS `~/Library/Application Support/智语言/`。

## 五、离线构建（可选）

依赖全部来自 crates.io（首次构建自动下载）。若目标环境无法联网：

1. 在有网机器上完成一次 `cargo build`（或 `cargo fetch`）；
2. 把本机 `%USERPROFILE%/.cargo/registry/src/index.crates.io-*/` 整目录拷贝到离线机器同位置；
3. 在离线机器的用户级 `~/.cargo/config.toml` 中加入源替换（表键必须 ASCII）：

```toml
[source.crates-io]
replace-with = "local-vendored"

[source.local-vendored]
directory = "C:/Users/<你>/.cargo/registry/src/index.crates.io-1949cf8c6b5b557f"
```

4. `cargo build --offline` 即可。


**注意**：仓库内 `.cargo/config.toml` 保持"无源替换"的开源状态，源替换只写在用户级配置里。

## 六、发布（两条命令）

发布流程就是两条标准命令，不需要脚本：

```sh
# 1. 构建（默认 target-dir=产出）
cargo build

# 2. 打包发布文件
cargo run --bin 产出发布
```

执行后产出（`产出发布.rs` 自动完成）：

```
发布/
└── 版本<号>/
    ├── 安装包/     # 安装包（zip）
    ├── 便携版/     # 免安装便携版
    ├── 校验/       # 哈希校验文件
    └── 工具链/     # 精简工具链（若 文件/工具链/精简工具链 存在）
```

**版本号唯一真相源** = `源码/版本管理器/Cargo.toml` 的 `version` 字段（当前 `0.0.1`）。发布包名、版本目录、包内结构均自动跟随该字段，改版本只改这一处。

发布前建议跑一遍测试门禁（见 `测试/3测试脚本/门禁使用规范.md`，四个权威入口：精准测试门禁.ps1 / 双模差分对账.py / 死代码审计.py / 导出快照一致性校验.ps1）。

## 七、常见问题

- **中文路径**：构建、运行、测试对中文路径/文件名完全支持（语言本身要求中文标识符）。
- **cache 与指纹**：构建缓存失效由内容指纹驱动（`版本管理器/build.rs` 哈希 前端/编译器/基础/解释器 源树），改 Rust 源码后重跑 `cargo build` 即可，无需手工清理；构建异常时可删除 `产出/debug` 重建。
- **不要把 target 改回默认**：`.cargo/config.toml` 的 `[build] target-dir = "产出"` 是双模链接（base.lib）与缓存指纹的前提。
- **双模**：解释模式与编译模式共用同一前端与 base；编译模式首次运行会自动重建 base 静态库（按指纹）。
